Pandas Library Comprehensive CheatSheet

Section 1: Core Data Structures & Creation

Series and DataFrame Construction

A Series is a one-dimensional labeled array; a DataFrame is a two-dimensional labeled table made up of Series sharing a common index. Both carry an explicit index alongside the data, which is what distinguishes pandas structures from raw NumPy arrays.

Constructor input Series DataFrame
List / array pd.Series([1, 2, 3]) pd.DataFrame([[1, 2], [3, 4]])
Dict pd.Series({"a": 1, "b": 2}) (keys become index) pd.DataFrame({"col1": [1, 2], "col2": [3, 4]}) (keys become columns)
NumPy array pd.Series(np.array([1, 2, 3])) pd.DataFrame(np.array([[1, 2], [3, 4]]))
List of dicts (records) not applicable pd.DataFrame([{"a": 1, "b": 2}, {"a": 3, "b": 4}])
Scalar pd.Series(5, index=[0, 1, 2]) pd.DataFrame(5, index=[0, 1], columns=["a", "b"]) 
import pandas as pd
import numpy as np

# Series from a list, with a custom index
s = pd.Series([10, 20, 30], index=["a", "b", "c"])

# Series from a dict — keys become the index automatically
s2 = pd.Series({"x": 1, "y": 2, "z": 3})

# DataFrame from a dict of lists — most common construction pattern
df = pd.DataFrame({"name": ["Alice", "Bob", "Carol"], "age": [25, 30, 35], "city": ["NYC", "LA", "SF"]})

# DataFrame from a list of dicts (records) — useful when data arrives row-by-row
records = [{"name": "Alice", "age": 25}, {"name": "Bob", "age": 30}]
df2 = pd.DataFrame(records)

# DataFrame from a NumPy array, with explicit column and index labels
arr = np.array([[1, 2, 3], [4, 5, 6]])
df3 = pd.DataFrame(arr, columns=["a", "b", "c"], index=["row1", "row2"])

# DataFrame.from_records and DataFrame.from_dict are explicit alternatives to the generic constructor
df4 = pd.DataFrame.from_dict({"a": [1, 2], "b": [3, 4]}, orient="columns")

A key gotcha: when constructing a DataFrame from a dict of lists, all lists must be the same length, or pandas raises an error. When constructing from a dict of scalars, pandas broadcasts the scalar across the length implied by any array-valued keys.

Attributes and Inspection

Once you have a Series or DataFrame, these attributes and methods are the standard first pass at understanding what you’re working with.

Attribute / method Purpose
.dtypes Data type of each column (DataFrame) or the Series
.shape (rows, columns) tuple
.columns Column labels (DataFrame only)
.index Row labels
.info() Summary: dtypes, non-null counts, memory usage
.describe() Summary statistics for numeric (or all) columns
.head(n) / .tail(n) First / last n rows (default 5)
.values Underlying NumPy array
.size Total number of elements
.ndim Number of dimensions (1 for Series, 2 for DataFrame) 
df = pd.DataFrame({"name": ["Alice", "Bob", "Carol"], "age": [25, 30, 35], "score": [88.5, 92.1, 79.3]})

df.dtypes        # name: object, age: int64, score: float64
df.shape          # (3, 3)
df.columns        # Index(['name', 'age', 'score'], dtype='object')
df.index          # RangeIndex(start=0, stop=3, step=1)
df.info()         # dtypes, non-null counts, memory usage summary
df.describe()     # count, mean, std, min, quartiles, max for numeric columns
df.head(2)        # first 2 rows
df.tail(2)        # last 2 rows

# describe() on non-numeric data shows count, unique, top, freq instead
df["name"].describe()

# include='all' forces describe to summarize every column regardless of dtype
df.describe(include="all")

A quick note on terminology you’ll see throughout the rest of this sheet: object dtype usually means strings (or mixed types) unless you’ve explicitly converted to pandas’ newer nullable string dtype, which we’ll cover in Section 3.

Section 2: Indexing, Selection & Data Alignment

Label vs. Position Based Indexing

Pandas gives you two parallel systems for selecting data: loc works by label, iloc works by integer position. Mixing them up is one of the most common sources of subtle bugs, so it’s worth being precise about which one you’re using.

Accessor Basis Includes end of slice? Typical use
.loc[] Label Yes (inclusive) Select by row/column name
.iloc[] Integer position No (exclusive, like Python slicing) Select by numeric position
.at[] Label n/a (single value) Fast scalar access by label
.iat[] Integer position n/a (single value) Fast scalar access by position 
df = pd.DataFrame({"name": ["Alice", "Bob", "Carol", "Dave"], "age": [25, 30, 35, 40], "city": ["NYC", "LA", "SF", "NYC"]}, index=["r1", "r2", "r3", "r4"])

# loc — label based, end of slice is INCLUDED
df.loc["r1"]                  # single row by label, returns a Series
df.loc["r1":"r3"]             # rows r1 through r3 inclusive
df.loc[:, "name"]             # all rows, single column
df.loc["r1":"r3", ["name", "age"]]   # row slice + specific columns

# iloc — position based, end of slice is EXCLUDED (like normal Python slicing)
df.iloc[0]                    # first row
df.iloc[0:2]                  # first two rows (positions 0 and 1)
df.iloc[:, 0]                 # all rows, first column
df.iloc[0:2, [0, 1]]          # first two rows, first two columns

# at / iat — fast single scalar lookups, faster than loc/iloc for one value
df.at["r1", "age"]            # scalar value at label r1, column age
df.iat[0, 1]                  # scalar value at position (0, 1)

Boolean Masking and Conditional Selection

Boolean masks are the primary way to filter rows based on a condition. A mask is just a Series of True/False values, aligned to the DataFrame’s index, that you pass into the indexer.

df = pd.DataFrame({"name": ["Alice", "Bob", "Carol", "Dave"], "age": [25, 30, 35, 40], "city": ["NYC", "LA", "SF", "NYC"]})

# Single condition
df[df["age"] > 30]

# Multiple conditions — use & and |, NOT 'and'/'or', and wrap each condition in parentheses
df[(df["age"] > 25) & (df["city"] == "NYC")]

# isin() for membership tests against a list of values
df[df["city"].isin(["NYC", "LA"])]

# ~ negates a boolean mask
df[~df["city"].isin(["SF"])]

# loc combined with a boolean mask lets you select columns at the same time
df.loc[df["age"] > 30, ["name", "city"]]

# query() offers a more readable alternative for complex conditions (covered further in Section 8)
df.query("age > 25 and city == 'NYC'")

A common gotcha: chaining indexing operations like df[df["age"] > 30]["age"] = 40 can trigger a SettingWithCopyWarning and may silently fail to update the original DataFrame. Use df.loc[df["age"] > 30, "age"] = 40 instead — this is covered in depth in Section 12.

Setting Values and Index Manipulation

df = pd.DataFrame({"name": ["Alice", "Bob", "Carol"], "age": [25, 30, 35]})

# Setting values via loc — always prefer this over chained indexing
df.loc[0, "age"] = 26
df.loc[df["name"] == "Bob", "age"] = 31

# set_index — promote a column to become the index
df2 = df.set_index("name")

# reset_index — move the index back into a column, restoring a default RangeIndex
df3 = df2.reset_index()

# reset_index with drop=True discards the old index instead of keeping it as a column
df4 = df2.reset_index(drop=True)

# rename the index or columns directly
df.rename(columns={"name": "full_name"}, inplace=True)
df.index.name = "row_id"

Data Alignment During Arithmetic, Reindex, and Align

One of pandas’ most important (and sometimes surprising) behaviors is automatic alignment: when you perform arithmetic between two Series or DataFrames, pandas aligns them by index label first, not by position. Any labels that don’t match on both sides produce NaN.

s1 = pd.Series([1, 2, 3], index=["a", "b", "c"])
s2 = pd.Series([10, 20, 30], index=["b", "c", "d"])

# Alignment happens automatically — only matching labels combine cleanly
s1 + s2
# a     NaN  (only in s1)
# b    12.0
# c    23.0
# d     NaN  (only in s2)

# reindex — conform a Series/DataFrame to a new index, introducing NaN for missing labels
s1.reindex(["a", "b", "c", "d"])

# reindex with a fill value instead of NaN
s1.reindex(["a", "b", "c", "d"], fill_value=0)

# align — explicitly align two objects and return both, with a chosen join type
aligned_s1, aligned_s2 = s1.align(s2, join="outer")
aligned_s1, aligned_s2 = s1.align(s2, join="inner")   # keep only labels present in both

This alignment behavior is why it’s important to check your indexes before combining data — a mismatched index is a common source of unexpected NaN values that has nothing to do with missing data in the original source.

MultiIndex / Hierarchical Indexing

A MultiIndex lets a Series or DataFrame have more than one level of row (or column) labels, which is useful for representing higher-dimensional data in a 2D table.

arrays = [["NYC", "NYC", "LA", "LA"], ["2023", "2024", "2023", "2024"]]
index = pd.MultiIndex.from_arrays(arrays, names=["city", "year"])
df = pd.DataFrame({"sales": [100, 110, 90, 95]}, index=index)

# Select by outer level
df.loc["NYC"]

# Select by both levels
df.loc[("NYC", "2023")]

# xs — cross-section, select a level without dropping the rest of the structure
df.xs("2023", level="year")

# swaplevel — reorder the levels of a MultiIndex
df_swapped = df.swaplevel("city", "year")

# sort by index level — important for performance and for slicing to work correctly
df_sorted = df.sort_index(level="city")

# from_tuples and from_product are other common MultiIndex constructors
pd.MultiIndex.from_tuples([("NYC", 2023), ("NYC", 2024)], names=["city", "year"])
pd.MultiIndex.from_product([["NYC", "LA"], [2023, 2024]], names=["city", "year"])

A practical note: many MultiIndex slicing operations require the index to be sorted first (sort_index()), or pandas will raise a PerformanceWarning or, in some cases, an error on partial slices.

Section 3: Data Cleaning & Dtypes

Missing Data

Pandas represents missing data using NaN (for numeric/object data), NaT (for datetime data), or pd.NA (the newer, dtype-agnostic missing value marker used by nullable dtypes). Handling missing data well starts with reliably detecting it.

Method Purpose
isna() / isnull() Boolean mask of missing values (identical, isna is the modern preferred name)
notna() / notnull() Inverse of isna()
fillna(value) Replace missing values with a specified value or method
dropna() Remove rows or columns containing missing values
interpolate() Fill missing values using interpolation (e.g. linear) 
df = pd.DataFrame({"name": ["Alice", "Bob", None, "Dave"], "age": [25, np.nan, 35, 40], "score": [88.5, 92.1, np.nan, 79.3]})

# Detect missing values
df.isna()                     # DataFrame of True/False
df.isna().sum()               # count of missing values per column
df["age"].isna()              # mask for a single column

# fillna — replace with a constant, or a per-column dict of values
df.fillna(0)
df.fillna({"name": "Unknown", "age": df["age"].mean()})

# fillna with a method — forward-fill or backward-fill
df.fillna(method="ffill")     # propagate last valid value forward
df.fillna(method="bfill")     # propagate next valid value backward

# dropna — remove rows with any missing value (default), or all missing, or based on a subset
df.dropna()                          # drop rows with any NaN
df.dropna(how="all")                 # drop rows where every value is NaN
df.dropna(subset=["age"])            # drop rows where 'age' specifically is NaN
df.dropna(axis=1)                    # drop columns instead of rows

# interpolate — fill gaps using a numeric method, common for time series
df["age"].interpolate(method="linear")

A key gotcha: 0, "", and False are not treated as missing by pandas — only NaN, None, and NaT are. Also, comparing NaN == NaN returns False, which is why isna() exists rather than direct equality checks.

Dtype Conversion, Including Nullable Dtypes

Method Purpose
astype(dtype) Explicit conversion to a specified dtype
pd.to_numeric() Convert to numeric, with error handling options
pd.to_datetime() Convert to datetime (covered in Section 10)
convert_dtypes() Infer the best nullable dtype automatically 
df = pd.DataFrame({"a": ["1", "2", "3"], "b": [1.0, 2.0, 3.0], "c": ["x", "y", "z"]})

# astype — explicit, direct conversion
df["a"] = df["a"].astype(int)
df["b"] = df["b"].astype("int64")

# to_numeric handles messier data with an errors argument
messy = pd.Series(["1", "2", "not_a_number"])
pd.to_numeric(messy, errors="coerce")   # invalid parsing becomes NaN
pd.to_numeric(messy, errors="ignore")   # leaves the original values unchanged if any fail

# Traditional NumPy-backed dtypes can't represent missing integers cleanly —
# int64 columns silently upcast to float64 the moment a NaN is introduced
s = pd.Series([1, 2, None])
s.dtype    # float64, not int64

# Nullable dtypes solve this by using pd.NA and preserving the integer/boolean type
s_nullable = pd.Series([1, 2, None], dtype="Int64")    # capital I — nullable integer
s_nullable.dtype    # Int64
b_nullable = pd.Series([True, False, None], dtype="boolean")
str_nullable = pd.Series(["a", "b", None], dtype="string")

# convert_dtypes() infers the best nullable dtype for every column automatically
df.convert_dtypes()

The nullable dtypes (Int64, Float64, boolean, string — note the capitalization) are distinct from the classic NumPy-backed int64, float64, bool, and object dtypes. They exist specifically to let integer and boolean columns hold missing values without being silently upcast to float64 or object.

Categorical Data

The category dtype stores a fixed set of possible values (categories) plus an integer code for each row, which is both memory-efficient and semantically useful for data with a limited number of distinct values.

df = pd.DataFrame({"grade": ["B", "A", "C", "A", "B"]})

# Convert to category dtype
df["grade"] = df["grade"].astype("category")
df["grade"].dtype    # CategoryDtype

# Ordered categoricals encode a meaningful ranking, enabling comparison operators
grade_order = pd.CategoricalDtype(categories=["C", "B", "A"], ordered=True)
df["grade"] = df["grade"].astype(grade_order)
df["grade"] > "B"    # now works meaningfully because the category is ordered

# .cat accessor exposes category-specific operations
df["grade"].cat.categories             # the distinct categories
df["grade"].cat.codes                  # integer codes backing each value
df["grade"].cat.add_categories(["D"])  # add a new possible category
df["grade"].cat.remove_unused_categories()
df["grade"].cat.rename_categories({"A": "Excellent"})

Categoricals are worth reaching for whenever a column has a small, repeated set of string values (status flags, grades, regions) — they reduce memory usage substantially compared to object dtype and speed up groupby operations on that column.

Duplicates, Renaming, Replacing Values, and Detecting Inconsistencies

df = pd.DataFrame({"name": ["Alice", "Bob", "Alice", "Carol"], "age": [25, 30, 25, 35]})

# Detecting and removing duplicates
df.duplicated()                        # boolean mask, True for repeat rows (keeps first occurrence as False)
df.duplicated(subset=["name"])         # check duplicates based on specific columns only
df.drop_duplicates()                   # remove duplicate rows, keeping the first by default
df.drop_duplicates(keep="last")        # keep the last occurrence instead
df.drop_duplicates(subset=["name"], keep=False)   # drop all rows involved in any duplication

# Renaming columns or index labels
df.rename(columns={"name": "full_name"})
df.rename(index={0: "row_zero"})

# Replacing values
df["name"].replace("Alice", "Alicia")
df.replace({"name": {"Alice": "Alicia"}, "age": {25: 26}})
df["name"].replace(["Alice", "Bob"], ["Alicia", "Robert"])   # replace multiple values at once

# Detecting inconsistent or invalid values, e.g. unexpected categories or out-of-range numbers
df["age"].unique()                     # inspect distinct values to spot anomalies
df["age"].between(0, 120)              # boolean mask flagging plausible vs implausible ages
df[~df["age"].between(0, 120)]         # rows with implausible ages worth investigating

A practical workflow note: unique(), value_counts(), and describe() (from Section 1) are your best early tools for spotting inconsistent data — typos in categorical columns, unexpected nulls disguised as strings like "N/A", or numeric values outside a plausible range — before you commit to a cleaning strategy.

Section 4: Combining Data

concat

pd.concat() stacks pandas objects together along an axis — rows by default, or columns. It does not align on keys the way a merge does; it simply lines objects up based on their index (or ignores it, if you ask it to).

df1 = pd.DataFrame({"name": ["Alice", "Bob"], "age": [25, 30]})
df2 = pd.DataFrame({"name": ["Carol", "Dave"], "age": [35, 40]})

# Stack rows (axis=0, the default) — like appending one DataFrame below another
pd.concat([df1, df2])

# ignore_index resets to a fresh RangeIndex instead of keeping the original indexes,
# which otherwise repeat (0, 1, 0, 1) across the stacked pieces
pd.concat([df1, df2], ignore_index=True)

# Stack columns side by side (axis=1) — aligns by index
df3 = pd.DataFrame({"score": [88, 92]})
pd.concat([df1, df3], axis=1)

# join controls how mismatched indexes/columns are handled — 'outer' (default) keeps everything,
# 'inner' keeps only what's shared
pd.concat([df1, df2], join="outer")
pd.concat([df1, df2], join="inner")

# keys creates a MultiIndex identifying which original object each row came from
pd.concat([df1, df2], keys=["batch1", "batch2"])

merge / join

pd.merge() combines DataFrames based on shared key columns (or indexes), similar to a SQL join. .join() is a convenience method on DataFrame that’s optimized for combining on the index specifically.

Join type how= value Result
Inner "inner" (default) Only rows with matching keys in both
Left "left" All rows from left, matched where possible
Right "right" All rows from right, matched where possible
Outer "outer" All rows from both, matched where possible
Cross "cross" Cartesian product of both DataFrames 
customers = pd.DataFrame({"customer_id": [1, 2, 3], "name": ["Alice", "Bob", "Carol"]})
orders = pd.DataFrame({"customer_id": [1, 2, 2, 4], "amount": [100, 200, 150, 300]})

# Basic merge on a shared column name
pd.merge(customers, orders, on="customer_id", how="inner")
pd.merge(customers, orders, on="customer_id", how="left")
pd.merge(customers, orders, on="customer_id", how="outer")

# Merging when key column names differ between the two DataFrames
orders2 = orders.rename(columns={"customer_id": "cust_id"})
pd.merge(customers, orders2, left_on="customer_id", right_on="cust_id")

# Merging on the index instead of a column
pd.merge(customers.set_index("customer_id"), orders.set_index("customer_id"), left_index=True, right_index=True)

# suffixes — control naming when both frames share a non-key column name
a = pd.DataFrame({"id": [1, 2], "value": [10, 20]})
b = pd.DataFrame({"id": [1, 2], "value": [100, 200]})
pd.merge(a, b, on="id", suffixes=("_left", "_right"))

# validate — assert the expected relationship between keys, raising an error if violated
pd.merge(customers, orders, on="customer_id", validate="one_to_many")
# common validate values: "one_to_one", "one_to_many", "many_to_one", "many_to_many"

# indicator — add a column showing which side(s) each row's key came from
pd.merge(customers, orders, on="customer_id", how="outer", indicator=True)
# adds a '_merge' column with values: 'left_only', 'right_only', 'both'

# .join() — convenience method, defaults to joining on index
customers_indexed = customers.set_index("customer_id")
orders_indexed = orders.set_index("customer_id")
customers_indexed.join(orders_indexed, how="left")

validate= is worth using whenever you have an assumption about the relationship between your keys — for example, expecting each customer to appear once in customers and possibly many times in orders. If that assumption is wrong, pandas raises an error instead of silently producing a row-multiplied result, which is a common source of quiet bugs in merges.

Comparison Table: concat vs. merge vs. join

Feature concat merge join
Primary purpose Stack objects along an axis Combine on key columns/index Combine on index (convenience)
Aligns on keys No (index-based only) Yes Yes (index-based)
SQL-style join types No Yes (how=) Yes (how=)
Can stack more than two objects at once Yes No (pairwise only) Limited (via list of DataFrames)
Typical use case Appending batches, combining columns Relational-style joins on keys Quick joins when already indexed

Section 5: GroupBy & Aggregation

GroupBy Mechanics (Split-Apply-Combine)

groupby() implements the split-apply-combine pattern: split the data into groups based on some key, apply a function to each group independently, then combine the results back together. The groupby() call itself is lazy — it produces a DataFrameGroupBy object, and nothing is computed until you call an aggregation or other method on it.

df = pd.DataFrame({"city": ["NYC", "LA", "NYC", "LA", "SF"], "category": ["A", "A", "B", "B", "A"], "sales": [100, 200, 150, 250, 300]})

# Group by a single column
grouped = df.groupby("city")
grouped.sum()                    # sums all numeric columns per group
grouped["sales"].sum()           # sum a single column per group

# Group by multiple columns — produces a MultiIndex result
df.groupby(["city", "category"])["sales"].sum()

# as_index=False keeps the group keys as regular columns instead of the index
df.groupby("city", as_index=False)["sales"].sum()

# Iterating over groups directly
for city, group_df in df.groupby("city"):
    print(city, group_df["sales"].mean())

# get_group retrieves a single group as its own DataFrame
grouped.get_group("NYC")

# size() vs count() — size counts rows including NaN, count excludes NaN per column
grouped.size()
grouped.count()

Aggregation, Transform, and Filter

Method Returns Purpose
agg() One row per group Summarize each group down to a value (or several)
transform() Same shape as input Apply a function per group, broadcast back to original shape
filter() Subset of original rows Keep/drop entire groups based on a group-level condition 
df = pd.DataFrame({"city": ["NYC", "LA", "NYC", "LA", "SF"], "sales": [100, 200, 150, 250, 300]})

# agg with a single function
df.groupby("city")["sales"].agg("sum")

# agg with multiple functions at once
df.groupby("city")["sales"].agg(["sum", "mean", "count"])

# agg with different functions per column
df.groupby("city").agg({"sales": ["sum", "mean"]})

# Named aggregation — clean, explicit column naming for the result
df.groupby("city").agg(total_sales=("sales", "sum"), avg_sales=("sales", "mean"), num_orders=("sales", "count"))

# transform — returns a result the same length as the original, useful for group-relative calculations
df["sales_pct_of_city_total"] = df["sales"] / df.groupby("city")["sales"].transform("sum")
df["sales_vs_city_mean"] = df["sales"] - df.groupby("city")["sales"].transform("mean")

# filter — keep only groups meeting a group-level condition
df.groupby("city").filter(lambda g: g["sales"].sum() > 300)

# apply — most flexible but slowest; use when agg/transform can't express the logic
df.groupby("city").apply(lambda g: g.nlargest(1, "sales"))

The distinction between agg and transform is the one to internalize: agg collapses each group to a summary (fewer rows than the input), while transform returns a result aligned to the original shape — which is exactly what you want when adding a new column derived from a group statistic, like “this row’s sales as a percentage of its city’s total.”

Pivot Tables and Crosstab

pivot_table() is essentially a groupby with a reshaping step built in — it groups by one or more keys and lays the result out as a table, with an aggregation function applied to the values.

df = pd.DataFrame({"city": ["NYC", "LA", "NYC", "LA"], "category": ["A", "A", "B", "B"], "sales": [100, 200, 150, 250]})

# Basic pivot_table — rows from index, columns from columns, values aggregated
df.pivot_table(index="city", columns="category", values="sales", aggfunc="sum")

# Multiple aggregation functions at once
df.pivot_table(index="city", columns="category", values="sales", aggfunc=["sum", "mean"])

# fill_value handles combinations that don't exist in the data
df.pivot_table(index="city", columns="category", values="sales", aggfunc="sum", fill_value=0)

# margins adds row/column totals
df.pivot_table(index="city", columns="category", values="sales", aggfunc="sum", margins=True)

# crosstab — similar idea, but built for frequency counts of categorical combinations by default
pd.crosstab(df["city"], df["category"])                     # counts of each combination
pd.crosstab(df["city"], df["category"], values=df["sales"], aggfunc="sum")   # same as pivot_table with sum
pd.crosstab(df["city"], df["category"], normalize=True)      # proportions instead of raw counts

The practical difference: pivot_table takes an existing DataFrame and reshapes/aggregates it, while crosstab typically takes raw array-like inputs (often two Series) and is most commonly reached for when you just want a quick frequency table of two categorical variables.

Section 6: Sorting, Ranking & Window/Sequential Functions

Sorting and Ranking

df = pd.DataFrame({"name": ["Alice", "Bob", "Carol", "Dave"], "age": [30, 25, 35, 25], "score": [88, 92, 79, 95]})

# sort_values — sort by one or more columns
df.sort_values("age")
df.sort_values("age", ascending=False)
df.sort_values(["age", "score"])                     # sort by age first, then score as tiebreaker
df.sort_values(["age", "score"], ascending=[True, False])   # different direction per column

# sort_index — sort by the row (or column) labels instead of values
df.sort_index()
df.sort_index(axis=1)          # sort columns alphabetically
df.sort_index(ascending=False)

# na_position controls where missing values land when sorting
df.sort_values("age", na_position="first")

# rank — assign ranks to values, with several tie-breaking strategies
df["age_rank"] = df["age"].rank()                    # average rank for ties (default)
df["age_rank_min"] = df["age"].rank(method="min")    # tied values get the lowest rank
df["age_rank_dense"] = df["age"].rank(method="dense")  # like min, but no gaps between rank values

# nlargest / nsmallest — efficient shortcut for top/bottom N rows by a column, faster than sort + head
df.nlargest(2, "score")
df.nsmallest(2, "age")
df.nlargest(2, ["age", "score"])   # tiebreak on a second column

Rolling, Expanding, and Exponentially Weighted Windows

Window functions compute a statistic over a sliding (or growing) subset of the data, which is central to time series and trend analysis.

Method Window behavior
rolling(n) Fixed-size sliding window of the last n observations
expanding() Growing window that includes everything from the start up to the current point
ewm() Exponentially weighted window, giving more weight to recent observations 
s = pd.Series([10, 12, 15, 11, 18, 20, 17, 22])

# rolling — fixed-size moving window
s.rolling(window=3).mean()       # 3-period moving average; first 2 values are NaN
s.rolling(window=3).sum()
s.rolling(window=3, min_periods=1).mean()   # allow partial windows at the start instead of NaN

# expanding — cumulative window that grows with each row
s.expanding().mean()             # running average from the start through the current row
s.expanding().sum()              # running total

# ewm — exponentially weighted, more responsive to recent values than a simple rolling mean
s.ewm(span=3).mean()
s.ewm(alpha=0.5).mean()          # alpha directly controls the decay rate

# rolling also works grouped, combining with groupby for per-group rolling stats
df = pd.DataFrame({"city": ["NYC", "NYC", "NYC", "LA", "LA", "LA"], "sales": [100, 110, 105, 200, 190, 210]})
df.groupby("city")["sales"].rolling(window=2).mean()

shift, diff, pct_change, and Cumulative Functions

These operate row-to-row (or across a lag), and come up constantly in time series work, finance, and feature engineering.

s = pd.Series([10, 12, 15, 11, 18])

# shift — move values forward or backward by n positions, leaving NaN in the gap
s.shift(1)             # each value moved down by one row (typical "previous value" pattern)
s.shift(-1)             # each value moved up by one row ("next value")

# diff — difference between the current value and a prior one (default: 1 row back)
s.diff()                # equivalent to s - s.shift(1)
s.diff(periods=2)       # difference against the value two rows back

# pct_change — percentage change from the prior value, common for returns/growth rates
s.pct_change()
s.pct_change(periods=2)

# Cumulative functions — running calculations down the Series
s.cumsum()              # running total
s.cummax()               # running maximum seen so far
s.cummin()               # running minimum seen so far
s.cumprod()              # running product

# cumcount — commonly used within groupby to number rows within each group
df = pd.DataFrame({"city": ["NYC", "NYC", "LA", "LA", "LA"]})
df.groupby("city").cumcount()       # 0, 1, 0, 1, 2 — position within each group

A common pattern worth internalizing: shift combined with a groupby is how you compute “previous value within this group” — for example, df.groupby("city")["sales"].shift(1) gives each row the prior sales figure for that same city, which is the building block for group-aware diff and pct_change calculations.

Section 7: Reshaping Data

Wide vs. Long Format

Before the specific methods, it helps to fix the vocabulary: wide format has one row per entity with separate columns for each measurement or time point; long format has one row per entity-measurement combination, with a column identifying which measurement it is. Most pandas operations (groupby, plotting, many statistical tools) expect long format, while wide format is often more human-readable for display.

Wide format Long format
Example One row per person, columns math_score, english_score One row per person-subject pair, columns subject, score
Easier to read as-is Yes Not directly
Easier to groupby/aggregate/plot No Yes
Typical pandas tools pivot, pivot_table (long → wide) melt, stack (wide → long)

pivot / pivot_table vs. melt

long_df = pd.DataFrame({"student": ["Alice", "Alice", "Bob", "Bob"], "subject": ["math", "english", "math", "english"], "score": [90, 85, 78, 92]})

# pivot — reshape long to wide (requires unique index/column combinations, no aggregation)
wide_df = long_df.pivot(index="student", columns="subject", values="score")

# pivot_table — like pivot, but aggregates when there are duplicate index/column combinations
# (also covered in Section 5 as a groupby-adjacent tool)
long_df.pivot_table(index="student", columns="subject", values="score", aggfunc="mean")

# melt — reshape wide to long, the inverse of pivot
wide_df_reset = wide_df.reset_index()
pd.melt(wide_df_reset, id_vars="student", value_vars=["math", "english"], var_name="subject", value_name="score")

# melt without specifying value_vars melts every column except id_vars
pd.melt(wide_df_reset, id_vars="student")

The key distinction between pivot and pivot_table: pivot raises an error if the index/columns combination isn’t unique (it has no way to combine duplicates), while pivot_table requires an aggfunc precisely because it’s built to handle that case.

stack / unstack

stack and unstack move data between the columns and the (innermost level of the) row index, which is a related but distinct operation from pivot/melt — it works directly with MultiIndex structures.

df = pd.DataFrame({"math": [90, 78], "english": [85, 92]}, index=["Alice", "Bob"])

# stack — pivot columns into a new innermost row index level, producing a Series (long format)
stacked = df.stack()
# Alice  math       90
#        english    85
# Bob    math       78
#        english    92

# unstack — the inverse, pivot the innermost row index level back into columns
unstacked = stacked.unstack()

# unstack can target a specific level when there are multiple index levels
multi_df = pd.DataFrame({"score": [90, 85, 78, 92]}, index=pd.MultiIndex.from_tuples([("Alice", "math"), ("Alice", "english"), ("Bob", "math"), ("Bob", "english")], names=["student", "subject"]))
multi_df.unstack(level="subject")
multi_df.unstack(level=0)     # unstack by position instead of name

explode and wide_to_long

# explode — turn list-valued cells into separate rows, duplicating the other column values
df = pd.DataFrame({"student": ["Alice", "Bob"], "subjects": [["math", "english"], ["science"]]})
df.explode("subjects")
# Alice  math
# Alice  english
# Bob    science

# wide_to_long — a more configurable wide-to-long reshape for columns following a naming pattern
wide = pd.DataFrame({"id": [1, 2], "score_2022": [80, 70], "score_2023": [85, 75]})
pd.wide_to_long(wide, stubnames="score", i="id", j="year", sep="_")

explode is especially useful after reading in data where a column contains list-like values (common with JSON sources or comma-separated fields you’ve split into lists) — it’s the standard way to normalize that into one row per element.

Section 8: Applying Functions, Vectorized Operations & Chaining

Series.map, DataFrame.map, and DataFrame.apply

These three are easy to confuse, so it’s worth being precise about what each one operates on.

Method Operates on Element-wise or whole-object? Typical use
Series.map() A single Series Element-wise Substitute/transform each value, often via a dict or function
DataFrame.map() Every element of a DataFrame Element-wise Apply a function to every cell (replaces the deprecated applymap)
DataFrame.apply() Rows or columns of a DataFrame Whole Series at a time (row or column) Row-wise or column-wise computations, including those returning multiple values 
df = pd.DataFrame({"name": ["alice", "bob", "carol"], "age": [25, 30, 35], "score": [88, 92, 79]})

# Series.map — element-wise, works well with a dict for lookups/substitution
df["name"].map(str.upper)
df["grade_level"] = df["age"].map({25: "junior", 30: "mid", 35: "senior"})
df["name"].map(lambda x: x.capitalize())

# DataFrame.map — element-wise across the whole DataFrame (modern replacement for applymap)
df[["age", "score"]].map(lambda x: x * 2)

# DataFrame.apply — operates on entire rows or columns at once, not element by element
df[["age", "score"]].apply(lambda col: col.max() - col.min())          # axis=0 (default): one call per column
df[["age", "score"]].apply(lambda row: row["age"] + row["score"], axis=1)   # axis=1: one call per row

# apply can return multiple values per row, producing a new DataFrame
df[["age", "score"]].apply(lambda row: pd.Series({"total": row.sum(), "avg": row.mean()}), axis=1)

Vectorized Operations, Broadcasting, and Performance vs. apply

Pandas (via NumPy underneath) supports vectorized arithmetic directly on Series and DataFrames — operations applied to the whole array at once in compiled code, rather than looping in Python. This is almost always dramatically faster than apply, which under the hood still calls a Python function once per row or column.

df = pd.DataFrame({"price": [10, 20, 30], "quantity": [2, 3, 4]})

# Vectorized — fast, operates on the whole column at once
df["total"] = df["price"] * df["quantity"]

# Equivalent but slow — apply calls a Python function once per row
df["total"] = df.apply(lambda row: row["price"] * row["quantity"], axis=1)

# Broadcasting — a scalar (or shorter array) is automatically expanded to match shape
df["price_with_tax"] = df["price"] * 1.08
df["discounted"] = df["price"] - 5

# Vectorized string/comparison operations also avoid apply
df["is_expensive"] = df["price"] > 15

Rule of thumb: if a computation can be expressed as arithmetic, a comparison, or a built-in pandas/NumPy function, use the vectorized form. Reach for apply only when the logic genuinely can’t be vectorized — for example, calling an external function, complex conditional branching that doesn’t map to where/select, or row-wise logic involving multiple unrelated columns in a way vectorization can’t express.

where, mask, np.where, and np.select

df = pd.DataFrame({"score": [45, 72, 88, 55, 95]})

# where — keep values where condition is True, replace with NaN (or other value) elsewhere
df["score"].where(df["score"] >= 60)                    # fails become NaN
df["score"].where(df["score"] >= 60, other=0)            # fails become 0 instead

# mask — the inverse of where: replace values where condition is True
df["score"].mask(df["score"] < 60, other=0)               # same result as the where example above

# np.where — vectorized ternary, often used to create a new column based on a condition
df["result"] = np.where(df["score"] >= 60, "pass", "fail")

# np.select — vectorized version of multiple if/elif branches
conditions = [df["score"] >= 90, df["score"] >= 70, df["score"] >= 60]
choices = ["A", "B", "C"]
df["grade"] = np.select(conditions, choices, default="F")

pipe, assign, query/eval, and Building Readable Chains

df = pd.DataFrame({"name": ["Alice", "Bob", "Carol"], "age": [25, 30, 35], "score": [88, 92, 79]})

# pipe — pass the whole object through a custom function, enabling clean chaining
# of custom logic alongside built-in methods
def add_bonus(dataframe, bonus_amount):
    dataframe = dataframe.copy()
    dataframe["score"] = dataframe["score"] + bonus_amount
    return dataframe

result = df.pipe(add_bonus, bonus_amount=5)

# assign — add or modify columns without mutating the original, ideal for chaining
result = df.assign(score_doubled=df["score"] * 2, is_adult=df["age"] >= 18)

# assign with a lambda referencing columns being built in the same call
result = df.assign(age_plus_one=lambda d: d["age"] + 1)

# query — filter rows using a readable string expression instead of boolean masks
df.query("age > 25 and score >= 80")
threshold = 80
df.query("score >= @threshold")          # reference external variables with @

# eval — evaluate a string expression, often for creating a new column efficiently
df.eval("total = age + score")

# A full method chain combining several of these tools, avoiding intermediate variables
result = (df.query("age > 20").assign(bonus_score=lambda d: d["score"] + 5).sort_values("bonus_score", ascending=False).reset_index(drop=True))

Method chaining like the example above trades off a small readability cost (you have to read the whole chain to see the final result) against avoiding a proliferation of intermediate variable names and, in many cases, avoiding intermediate copies — most of these methods return a new object by default rather than mutating in place, which is what makes chaining them safe.

Section 9: String & Text Data

The .str Accessor and Common Methods

The .str accessor exposes vectorized string operations on a Series, mirroring Python’s built-in string methods but applying them element-wise across the whole column at once (and handling missing values gracefully rather than raising errors).

Method Purpose
.str.strip() / .lstrip() / .rstrip() Remove leading/trailing whitespace
.str.lower() / .upper() / .title() Change case
.str.len() Length of each string
.str.contains() Boolean mask for substring/pattern presence
.str.startswith() / .endswith() Boolean mask for prefix/suffix match
.str.split() Split each string into a list (or expand into columns)
.str.cat() Concatenate strings, optionally with a separator
.str.pad() / .str.zfill() Pad strings to a fixed width 
df = pd.DataFrame({"name": ["  Alice ", "bob", "CAROL", None], "email": ["alice@example.com", "bob@test.org", "carol@example.com", "dave@test.org"]})

# Cleaning whitespace and case
df["name"].str.strip()
df["name"].str.lower()
df["name"].str.title()

# Length
df["name"].str.len()

# contains — substring or pattern search, returns a boolean mask (NaN stays NaN by default)
df["email"].str.contains("example")

# startswith / endswith
df["email"].str.endswith(".org")

# split — returns a Series of lists by default
df["email"].str.split("@")

# split with expand=True returns separate columns instead of lists
df["email"].str.split("@", expand=True)

# split with a limit on the number of splits
df["email"].str.split("@", n=1, expand=True)

# cat — concatenate a Series with another string or Series
df["name"].str.strip().str.cat(df["email"], sep=" - ")

A practical chaining pattern: string cleaning operations chain naturally since each .str method returns a new Series — df["name"].str.strip().str.lower().str.title() runs all three transformations in one line.

Pattern Matching, Regex, and Missing Values in String Operations

df = pd.DataFrame({"text": ["Order #12345", "Order #67890", "No order number", None]})

# contains with regex (the default; set regex=False for a literal substring search)
df["text"].str.contains(r"\d+", regex=True)
df["text"].str.contains("Order", regex=False)      # literal match, slightly faster

# extract — pull out the first regex match into a new column, using a capture group
df["order_number"] = df["text"].str.extract(r"#(\d+)")

# extractall — pull out every match, not just the first, producing a MultiIndex result
df["text"].str.extractall(r"(\d+)")

# replace — regex-aware find and replace
df["text"].str.replace(r"#\d+", "#REDACTED", regex=True)
df["text"].str.replace("Order", "Purchase", regex=False)

# Handling missing values — most .str methods propagate NaN rather than raising an error
df["text"].str.upper()          # the None entry stays as NaN in the result

# na parameter on contains/match lets you control what missing rows evaluate to
df["text"].str.contains("Order", na=False)      # treat missing as False instead of NaN

# match — anchors the pattern to the start of the string (unlike contains, which searches anywhere)
df["text"].str.match(r"Order")

A useful habit: when filtering with .str.contains(), pass na=False explicitly if you plan to use the result as a boolean mask for selection — otherwise a row with a missing value produces NaN in the mask, which raises an error when used directly inside df[mask].

Section 10: Date & Time Handling

Datetime Conversion, Parsing, and the .dt Accessor

df = pd.DataFrame({"date_str": ["2023-01-15", "2023-02-20", "2023-03-10"], "value": [100, 150, 200]})

# to_datetime — the standard way to convert strings (or other types) into datetime objects
df["date"] = pd.to_datetime(df["date_str"])

# Explicit format speeds up parsing and avoids ambiguity (e.g. day-first vs month-first)
pd.to_datetime(["15/01/2023", "20/02/2023"], format="%d/%m/%Y")

# errors='coerce' turns unparseable values into NaT instead of raising
pd.to_datetime(["2023-01-15", "not_a_date"], errors="coerce")

# The .dt accessor exposes datetime components, mirroring how .str works for strings
df["date"].dt.year
df["date"].dt.month
df["date"].dt.day
df["date"].dt.dayofweek        # Monday=0 through Sunday=6
df["date"].dt.day_name()       # 'Monday', 'Tuesday', etc.
df["date"].dt.quarter
df["date"].dt.is_month_end     # boolean mask

DatetimeIndex, Time-Based Indexing, and Resampling

Setting a datetime column as the index unlocks time-aware slicing and resampling, which is one of the more powerful and pandas-specific workflows.

df = pd.DataFrame({"date": pd.date_range("2023-01-01", periods=10, freq="D"), "value": range(10)})
df = df.set_index("date")

# Time-based slicing — pass partial date strings directly
df["2023-01"]                       # all rows in January 2023
df["2023-01-03":"2023-01-06"]       # inclusive date range slice

# date_range — generate a sequence of dates, useful for building indexes or filling gaps
pd.date_range(start="2023-01-01", end="2023-01-10", freq="D")
pd.date_range(start="2023-01-01", periods=5, freq="M")     # month-end frequency
pd.date_range(start="2023-01-01", periods=5, freq="B")     # business days only

# resample — group by time period and aggregate, similar in spirit to groupby but time-aware
df.resample("W").sum()              # weekly totals
df.resample("M").mean()             # monthly averages
df.resample("D").ffill()            # upsample to daily, forward-filling gaps

# asfreq — change frequency without aggregating, just reindexing onto the new frequency
df.asfreq("D")

Timedeltas, Date Offsets, and Time Zones

# Timedelta — represents a duration
pd.Timedelta(days=5)
pd.Timedelta("2 days 3 hours")

# Subtracting two datetime columns produces a Timedelta Series
df = pd.DataFrame({"start": pd.to_datetime(["2023-01-01", "2023-01-05"]), "end": pd.to_datetime(["2023-01-10", "2023-01-08"])})
df["duration"] = df["end"] - df["start"]
df["duration_days"] = df["duration"].dt.days

# DateOffset — calendar-aware arithmetic, correctly handles month-end, leap years, etc.
df["start"] + pd.DateOffset(months=1)
df["start"] + pd.DateOffset(days=10)

# Common offset aliases used throughout freq= arguments
# 'D' day, 'B' business day, 'W' week, 'M' month end, 'MS' month start,
# 'Q' quarter end, 'Y' year end, 'H' hour, 'T'/'min' minute

# Time zones — localize a naive datetime, then convert between zones
ts = pd.Timestamp("2023-01-01 12:00:00")
ts_localized = ts.tz_localize("UTC")
ts_converted = ts_localized.tz_convert("America/New_York")

# tz_localize / tz_convert also work on an entire Series or DatetimeIndex
df["start"] = df["start"].dt.tz_localize("UTC")
df["start_ny"] = df["start"].dt.tz_convert("America/New_York")

A gotcha worth flagging: tz_localize assumes the datetime is naive (no timezone attached yet) and assigns a zone; calling it on an already-localized datetime raises an error. Use tz_convert when you want to shift a datetime that already has a timezone to a different one.

Reading Selected Columns, Parsing Dates/Dtypes, chunksize, and Encoding

# Read only specific columns — faster and lighter on memory for wide files
pd.read_csv("data.csv", usecols=["name", "age", "date"])

# Parse specific columns as dates during the read, rather than converting afterward
pd.read_csv("data.csv", parse_dates=["date"])

# Set dtypes explicitly during the read, avoiding pandas' automatic (sometimes wrong) inference
pd.read_csv("data.csv", dtype={"customer_id": "str", "amount": "float64"})

# Specify how missing values are represented in the source file
pd.read_csv("data.csv", na_values=["N/A", "missing", "-"])

# chunksize — read a large file in pieces instead of all at once, returning an iterator
for chunk in pd.read_csv("large_file.csv", chunksize=10000):
    process(chunk)     # process each chunk, e.g. filter/aggregate, then discard it

# Encoding issues are common with files from non-UTF-8 sources
pd.read_csv("data.csv", encoding="latin1")
pd.read_csv("data.csv", encoding="cp1252")

# Skip rows, specify a header row explicitly, or limit the number of rows read
pd.read_csv("data.csv", skiprows=2, header=0, nrows=1000)

chunksize is the standard approach when a file is too large to comfortably fit in memory: rather than loading everything at once, you read and process it piece by piece, typically accumulating results (sums, filtered rows, etc.) rather than holding the full dataset. It’s a common gotcha to forget that parse_dates and dtype during the initial read are both faster and more reliable than converting columns after the fact with astype/to_datetime, since pandas otherwise has to guess types across the whole file first.

Section 12: Performance & Common Gotchas

Chained Indexing, SettingWithCopyWarning, and Copy vs. View

df = pd.DataFrame({"name": ["Alice", "Bob", "Carol"], "age": [25, 30, 35]})

# Chained indexing — this may or may not modify the original df, and triggers a warning
df[df["age"] > 25]["age"] = 40        # SettingWithCopyWarning — avoid this pattern

# The safe alternative — a single loc call combining the filter and the assignment
df.loc[df["age"] > 25, "age"] = 40

# The ambiguity comes from not knowing whether df[df["age"] > 25] returns a view or a copy
# of the original data — pandas can't always tell, hence the warning rather than a silent choice

# .copy() makes the distinction explicit when you deliberately want an independent DataFrame
subset = df[df["age"] > 25].copy()
subset["age"] = 40                    # safe — subset is explicitly independent of df

# Without .copy(), modifying a slice you intend to keep separate can unexpectedly affect the original,
# or raise the warning, depending on whether pandas produced a view or a copy internally

The underlying rule: indexing operations in pandas sometimes return a view (sharing memory with the original) and sometimes a copy (independent), and which one you get isn’t always predictable from the syntax alone. .loc[] with a single combined call sidesteps the ambiguity entirely, and .copy() makes your intent explicit whenever you deliberately want a separate object.

Efficient Dtypes, Memory Usage, and Vectorization

df = pd.DataFrame({"category": ["A", "B", "A", "C"] * 1000, "amount": [10.5, 20.1, 15.3, 8.9] * 1000})

# memory_usage — inspect memory consumption per column
df.memory_usage(deep=True)          # deep=True gives accurate sizes for object columns

# Converting a repetitive object column to category can drastically cut memory usage
df["category"] = df["category"].astype("category")
df.memory_usage(deep=True)          # compare before/after

# Downcasting numeric types to the smallest sufficient dtype also saves memory
df["amount"] = pd.to_numeric(df["amount"], downcast="float")

# Vectorization over apply/loops — revisited from Section 8, but worth restating as a performance rule
df["amount_doubled"] = df["amount"] * 2                          # fast
df["amount_doubled"] = df["amount"].apply(lambda x: x * 2)       # slower, avoid when vectorization works

As a rule of thumb: convert low-cardinality object columns (a handful of repeated string values) to category, downcast numeric columns where the full range isn’t needed, and always prefer a vectorized expression over apply or a Python loop when one is available — the gap widens dramatically as data size grows.

Iteration (itertuples/iterrows) and Why to Avoid It

df = pd.DataFrame({"name": ["Alice", "Bob", "Carol"], "age": [25, 30, 35]})

# iterrows — returns (index, Series) pairs; readable but slow, and each row loses its original dtypes
for idx, row in df.iterrows():
    print(row["name"], row["age"])

# itertuples — returns namedtuples; noticeably faster than iterrows, but still a Python-level loop
for row in df.itertuples():
    print(row.name, row.age)

# Both exist mainly as an escape hatch for logic that truly can't be vectorized —
# prefer vectorized operations, apply, or map first

iterrows() is the slowest common option in pandas for row-by-row work, partly because it reconstructs a Series (with unified dtype) for every row, which can silently convert numeric columns to object. itertuples() is meaningfully faster and preserves types better, but both are still far slower than a vectorized equivalent — reach for iteration only after confirming the computation genuinely can’t be expressed with apply, map, where, or direct arithmetic.

Useful Display and Options Settings

# Control how much of a DataFrame prints to the console/notebook
pd.set_option("display.max_rows", 100)
pd.set_option("display.max_columns", 50)
pd.set_option("display.width", 120)

# Show full float precision instead of pandas' default rounding
pd.set_option("display.precision", 4)

# Suppress scientific notation for float columns
pd.set_option("display.float_format", "{:.2f}".format)

# reset_option reverts a setting back to its default
pd.reset_option("display.max_rows")

# get_option / describe_option inspect current or available settings
pd.get_option("display.max_rows")

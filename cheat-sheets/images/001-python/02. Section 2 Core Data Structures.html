Section 2: Core Data Structures

2.1 Lists

A list is an ordered, mutable, resizable sequence — the default go-to container for most LeetCode problems.

lst = [1, 2, 3]
lst = list()                # empty list
lst = [0] * 5                # [0, 0, 0, 0, 0] — repeat init

# access / slicing
lst[0]                      # first element
lst[-1]                     # last element
lst[1:3]                    # slice [start:end) — end excluded
lst[::-1]                   # reversed copy
lst[::2]                    # every 2nd element

# add
lst.append(4)                # add single item to end — amortized O(1)
lst.extend([5, 6])            # add multiple items to end — O(k)
lst.insert(0, 99)             # insert at index — O(n), shifts elements

# remove
lst.pop()                    # remove & return last item — O(1)
lst.pop(0)                    # remove & return item at index — O(n)
lst.remove(99)                # remove first matching value — O(n)
lst.clear()                   # empty the list

# search / info
3 in lst                     # membership check — O(n)
lst.index(3)                  # first index of value — O(n)
lst.count(3)                  # count occurrences — O(n)
len(lst)                     # length — O(1)

# order
lst.sort()                    # in-place sort, ascending
lst.sort(reverse=True)         # descending
lst.sort(key=lambda x: -x)      # custom key
lst.reverse()                 # in-place reverse
sorted(lst)                   # returns NEW sorted list (doesn't mutate)

# copy (important! avoid aliasing bugs)
lst2 = lst.copy()              # shallow copy
lst2 = lst[:]                 # also shallow copy

Big-O quick reference:

Operation Complexity
index access lst[i] O(1)
append (end) amortized O(1)
pop (end) O(1)
insert / pop (front or middle) O(n)
search (in, .index()) O(n)
sort O(n log n)

Why “amortized” for append: a list overallocates capacity behind the scenes. Most appends just fill the spare space (O(1)), but occasionally the list must grow and copy all existing elements (O(n)). Averaged over many appends, the cost per append works out to O(1).

2.2 Tuples

A tuple is like a list but immutable — used for fixed collections, dict keys, and multi-return values.

t = (1, 2, 3)
t = 1, 2, 3                  # parens optional
single = (5,)                 # trailing comma required for 1-element tuple

t[0]                         # access — same indexing/slicing as list
t.count(1)                    # count occurrences
t.index(2)                    # first index of value

a, b, c = t                   # unpacking
x, *rest = t                  # x=1, rest=[2,3] — star unpacking

# immutable -> can be a dict key or set element (lists cannot)
d = {(0, 0): "origin"}

Hashability caveat: a tuple is only hashable — and therefore only usable as a dict key or set element — if every element inside it is hashable. (1, 2) works fine, but (1, [2, 3]) does not, because it contains a list.

d = {(1, [2, 3]): "x"}    # TypeError: unhashable type: 'list'

2.3 Dictionaries

A dict stores key-value pairs, backed by a hash table — O(1) average lookup/insert. Essential for frequency counts, memoization, and graph adjacency lists.

d = {"a": 1, "b": 2}
d = dict()                   # empty dict
d = {}                       # also empty dict

# access
d["a"]                       # KeyError if missing
d.get("a")                    # None if missing (safe access)
d.get("a", 0)                 # 0 if missing (default value)

# add / update
d["c"] = 3                    # add or overwrite
d.update({"d": 4, "e": 5})      # merge in multiple pairs
d.setdefault("f", 0)            # set key to default ONLY if missing, returns value

# remove
d.pop("a")                    # remove & return value, KeyError if missing
d.pop("a", None)               # safe remove with default
del d["b"]                    # remove key
d.clear()

# search / info
"a" in d                     # membership checks KEYS — O(1)
len(d)

# iteration
for key in d: ...
for key in d.keys(): ...
for value in d.values(): ...
for key, value in d.items(): ...   # most common pattern

# common LeetCode idiom: frequency counting
freq = {}
for ch in "hello":
    freq[ch] = freq.get(ch, 0) + 1

.keys(), .values(), .items() return view objects, not lists. A view is a live, dynamic window onto the dict — if the dict changes, the view reflects that change automatically, without needing to be recreated. Views also support in checks in O(1) and set-like operations (e.g. d.keys() & other_dict.keys()). If you need an actual list (e.g. to sort it or index into it), wrap it explicitly: list(d.keys()). Also, mutating the dict while iterating over one of these views raises a RuntimeError.

Big-O: lookup, insert, delete, in check — all O(1) average (O(n) worst case due to hash collisions, rarely relevant).

2.4 Sets

A set is an unordered collection of unique, hashable elements — backed by a hash table like dict. Great for deduplication and O(1) membership checks.

s = {1, 2, 3}
s = set()                    # empty set — NOT {} (that's an empty dict!)
s = set([1, 2, 2, 3])          # {1, 2, 3} — dedupes

# add / remove
s.add(4)                     # O(1)
s.remove(4)                   # O(1), KeyError if missing
s.discard(4)                  # O(1), no error if missing
s.pop()                      # removes & returns an arbitrary element — O(1)

# search / info
3 in s                       # O(1) membership check
len(s)

# set algebra (very common in LeetCode)
a = {1, 2, 3}
b = {2, 3, 4}
a | b                        # union -> {1,2,3,4}
a & b                        # intersection -> {2,3}
a - b                        # difference -> {1}
a ^ b                        # symmetric difference -> {1,4}

frozenset([1, 2, 3])           # immutable version — hashable, can go in a set/dict key

.pop() removes an arbitrary element, not a random one. “Arbitrary” means unspecified and implementation-dependent — determined by internal hash-table layout, not by a random-number generator. It’s unordered and unpredictable from the caller’s perspective, but it isn’t drawn via a randomized process, and it isn’t guaranteed to vary between runs.

Big-O: add, remove, in check — all O(1) average.

2.5 Strings

A str is an immutable sequence of characters. Any “mutation” creates a new string.

s = "hello"

# access / slicing — same as lists
s[0]                         # 'h'
s[::-1]                      # reversed string — common palindrome trick

# building / joining
"".join(["a", "b", "c"])       # "abc" — O(n), the correct way to concatenate many pieces
" ".join(["a", "b"])           # "a b"

# search
"lo" in s                    # substring check
s.find("lo")                  # index of substring, -1 if not found
s.index("lo")                 # like find, but raises ValueError if not found
s.count("l")                  # count occurrences

# transform
s.upper(); s.lower()
s.strip()                    # trim whitespace from both ends
s.strip("xy")                 # trim characters from both ends — see note below
s.replace("l", "L")            # replace all occurrences
s.split()                    # split on whitespace -> list
s.split(",")                  # split on delimiter
s.startswith("he"); s.endswith("lo")

# type checks
s.isdigit(); s.isalpha(); s.isalnum(); s.isupper(); s.islower(); s.isspace()

# formatting
f"{s} world"                  # f-string (preferred)
"{} world".format(s)           # .format()

# char <-> code point conversion (common in cipher/hash problems)
ord('a')                     # 97
chr(97)                      # 'a'

+ concatenation cost: a single s1 + s2 is O(n + m) — proportional to the combined length, since a new string is allocated and both are copied in. The real danger is doing this repeatedly inside a loop (result += ch each iteration): each += allocates a new string and re-copies everything accumulated so far, so total cost across the loop becomes O(n²). Always prefer collecting pieces in a list and calling "".join(list) once at the end.

strip("xy") does not remove the substring "xy". It treats the argument as a set of characters and strips any leading/trailing run made up of those characters, in any combination — not the literal sequence "xy".

"xyxyhelloxy".strip("xy")   # "hello" — strips leading/trailing x's and y's in any order
"xyxhelloxy".strip("xy")     # "hello" — same, order/count of x/y doesn't matter

2.6 Comprehensions

Compact syntax for building a list, dict, or set from an iterable in one line — extremely common in idiomatic Python and worth knowing cold.

# list comprehension
squares = [x**2 for x in range(5)]              # [0, 1, 4, 9, 16]
evens = [x for x in range(10) if x % 2 == 0]      # filter with condition
matrix_flat = [x for row in matrix for x in row]   # nested loop, flattens 2D -> 1D

# dict comprehension
squares_map = {x: x**2 for x in range(5)}          # {0:0, 1:1, 2:4, 3:9, 4:16}
inverted = {v: k for k, v in d.items()}             # swap keys/values

# set comprehension
unique_lengths = {len(w) for w in ["a", "bb", "cc"]}  # {1, 2}

# conditional expression inside a comprehension (ternary)
labels = ["even" if x % 2 == 0 else "odd" for x in range(5)]

Comprehensions are generally faster and more idiomatic than building the same result with a manual for loop and .append(), but nesting more than 2 levels deep hurts readability — drop to a regular loop at that point.

Section 1: Data Types & Operators

1.1 Primitive Types & Type Conversion

Python’s core primitive types:

Type Example Notes
int 5 whole numbers, arbitrary precision
float 3.14 decimal numbers
complex 3 + 4j real + imaginary part (z.real, z.imag)
str "hello" immutable text
bool True/False subclass of int — True==1, False==0
NoneType None represents “no value” 
type(x)                  # check type, e.g. <class 'int'>
isinstance(x, int)       # preferred way to check type (supports subclasses)

Type conversion (casting):

int("42")        # 42     str -> int
int(3.99)         # 3      float -> int (truncates toward 0, not rounds)
float("3.14")      # 3.14
str(42)           # "42"
bool(0)           # False
list("abc")        # ['a', 'b', 'c']
tuple([1, 2, 3])    # (1, 2, 3)

Mutability — whether a value can be changed in place after creation:

Mutable Immutable
list, dict, set, bytearray int, float, str, tuple, frozenset, bool, None, bytes, complex 
s = "abc"
s[0] = 'z'        # ERROR: str is immutable
lst = [1, 2, 3]
lst[0] = 99        # OK: list is mutable

Truthy / falsy — values Python treats as False or True in conditions:

  • Falsy: 0, 0.0, "", [], {}, (), set(), None, False
  • Truthy: everything else — including the string "0" and a list like [0], since a non-empty container/string is always truthy regardless of its contents.

1.2 Arithmetic, Comparison & Logical Operators

Arithmetic:

Operator Meaning Example Result
+ addition 7 + 3 10
- subtraction 7 - 3 4
* multiplication 7 * 3 21
/ true division 7 / 3 2.333... (always float)
// floor division 7 // 3 2 (int if both operands int)
% modulo 7 % 3 1
** exponent 7 ** 3 343

⚠️ Watch negative numbers: floor division rounds toward negative infinity, not toward zero, and % takes the sign of the divisor.

-7 // 2     # -4, not -3
-7 % 2      # 1

Comparison (return bool): ==, !=, >, <, >=, <=. Chainable:

1 < 2 < 3     # True — equivalent to (1 < 2) and (2 < 3)

Identity vs. equality — is / is not: == checks if values are equal; is checks if two names point to the same object in memory. They usually differ for mutable objects and can be surprising for numbers/strings due to interning.

a = [1, 2]
b = [1, 2]
a == b        # True  — same contents
a is b        # False — different objects in memory
c = a
c is a        # True  — same object

x = None
x is None      # True — always use `is None`, never `== None`, for None checks

Membership — in / not in: checks whether a value exists inside a container (works on list, tuple, str, dict (checks keys), set).

3 in [1, 2, 3]         # True
"a" in "cat"            # True — substring check for strings
5 not in {1, 2, 3}       # True
"key" in {"key": 1}      # True — checks dict keys, not values

Logical operators: and, or, not. They short-circuit: a or b returns a if truthy, otherwise b; a and b returns a if falsy, otherwise b.

x = 0 or "default"     # "default"

Operator precedence (high to low, most relevant subset): ** → unary +/- → * / // % → + - → comparisons/in/is → not → and → or.

2 + 3 * 4       # 14, not 20 — multiplication binds tighter
(2 + 3) * 4      # 20 — parentheses force order

⚠️ Classic precedence trap: ** binds tighter than unary minus, so the minus sign is applied after exponentiation:

-2 ** 2         # -4, not 4  — evaluated as -(2 ** 2)
(-2) ** 2        # 4  — parentheses needed to square -2

Augmented assignment — shorthand for updating a variable in place:

x += 1     # x = x + 1
x -= 1
x *= 2
x //= 2
x **= 2
x %= 3

Yes, agreed on all of these — they’re accurate corrections, not just style preferences. Here’s Section 2 updated with each fix.

Section 2: Core Data Structures

2.1 Lists

A list is an ordered, mutable, resizable sequence — the default go-to container for most LeetCode problems.

lst = [1, 2, 3]
lst = list()                # empty list
lst = [0] * 5                # [0, 0, 0, 0, 0] — repeat init

# access / slicing
lst[0]                      # first element
lst[-1]                     # last element
lst[1:3]                    # slice [start:end) — end excluded
lst[::-1]                   # reversed copy
lst[::2]                    # every 2nd element

# add
lst.append(4)                # add single item to end — amortized O(1)
lst.extend([5, 6])            # add multiple items to end — O(k)
lst.insert(0, 99)             # insert at index — O(n), shifts elements

# remove
lst.pop()                    # remove & return last item — O(1)
lst.pop(0)                    # remove & return item at index — O(n)
lst.remove(99)                # remove first matching value — O(n)
lst.clear()                   # empty the list

# search / info
3 in lst                     # membership check — O(n)
lst.index(3)                  # first index of value — O(n)
lst.count(3)                  # count occurrences — O(n)
len(lst)                     # length — O(1)

# order
lst.sort()                    # in-place sort, ascending
lst.sort(reverse=True)         # descending
lst.sort(key=lambda x: -x)      # custom key
lst.reverse()                 # in-place reverse
sorted(lst)                   # returns NEW sorted list (doesn't mutate)

# copy (important! avoid aliasing bugs)
lst2 = lst.copy()              # shallow copy
lst2 = lst[:]                 # also shallow copy

Big-O quick reference:

Operation Complexity
index access lst[i] O(1)
append (end) amortized O(1)
pop (end) O(1)
insert / pop (front or middle) O(n)
search (in, .index()) O(n)
sort O(n log n)

Why “amortized” for append: a list overallocates capacity behind the scenes. Most appends just fill the spare space (O(1)), but occasionally the list must grow and copy all existing elements (O(n)). Averaged over many appends, the cost per append works out to O(1).

2.2 Tuples

A tuple is like a list but immutable — used for fixed collections, dict keys, and multi-return values.

t = (1, 2, 3)
t = 1, 2, 3                  # parens optional
single = (5,)                 # trailing comma required for 1-element tuple

t[0]                         # access — same indexing/slicing as list
t.count(1)                    # count occurrences
t.index(2)                    # first index of value

a, b, c = t                   # unpacking
x, *rest = t                  # x=1, rest=[2,3] — star unpacking

# immutable -> can be a dict key or set element (lists cannot)
d = {(0, 0): "origin"}

Hashability caveat: a tuple is only hashable — and therefore only usable as a dict key or set element — if every element inside it is hashable. (1, 2) works fine, but (1, [2, 3]) does not, because it contains a list.

d = {(1, [2, 3]): "x"}    # TypeError: unhashable type: 'list'

2.3 Dictionaries

A dict stores key-value pairs, backed by a hash table — O(1) average lookup/insert. Essential for frequency counts, memoization, and graph adjacency lists.

d = {"a": 1, "b": 2}
d = dict()                   # empty dict
d = {}                       # also empty dict

# access
d["a"]                       # KeyError if missing
d.get("a")                    # None if missing (safe access)
d.get("a", 0)                 # 0 if missing (default value)

# add / update
d["c"] = 3                    # add or overwrite
d.update({"d": 4, "e": 5})      # merge in multiple pairs
d.setdefault("f", 0)            # set key to default ONLY if missing, returns value

# remove
d.pop("a")                    # remove & return value, KeyError if missing
d.pop("a", None)               # safe remove with default
del d["b"]                    # remove key
d.clear()

# search / info
"a" in d                     # membership checks KEYS — O(1)
len(d)

# iteration
for key in d: ...
for key in d.keys(): ...
for value in d.values(): ...
for key, value in d.items(): ...   # most common pattern

# common LeetCode idiom: frequency counting
freq = {}
for ch in "hello":
    freq[ch] = freq.get(ch, 0) + 1

.keys(), .values(), .items() return view objects, not lists. A view is a live, dynamic window onto the dict — if the dict changes, the view reflects that change automatically, without needing to be recreated. Views also support in checks in O(1) and set-like operations (e.g. d.keys() & other_dict.keys()). If you need an actual list (e.g. to sort it or index into it), wrap it explicitly: list(d.keys()). Also, mutating the dict while iterating over one of these views raises a RuntimeError.

Big-O: lookup, insert, delete, in check — all O(1) average (O(n) worst case due to hash collisions, rarely relevant).

2.4 Sets

A set is an unordered collection of unique, hashable elements — backed by a hash table like dict. Great for deduplication and O(1) membership checks.

s = {1, 2, 3}
s = set()                    # empty set — NOT {} (that's an empty dict!)
s = set([1, 2, 2, 3])          # {1, 2, 3} — dedupes

# add / remove
s.add(4)                     # O(1)
s.remove(4)                   # O(1), KeyError if missing
s.discard(4)                  # O(1), no error if missing
s.pop()                      # removes & returns an arbitrary element — O(1)

# search / info
3 in s                       # O(1) membership check
len(s)

# set algebra (very common in LeetCode)
a = {1, 2, 3}
b = {2, 3, 4}
a | b                        # union -> {1,2,3,4}
a & b                        # intersection -> {2,3}
a - b                        # difference -> {1}
a ^ b                        # symmetric difference -> {1,4}

frozenset([1, 2, 3])           # immutable version — hashable, can go in a set/dict key

.pop() removes an arbitrary element, not a random one. “Arbitrary” means unspecified and implementation-dependent — determined by internal hash-table layout, not by a random-number generator. It’s unordered and unpredictable from the caller’s perspective, but it isn’t drawn via a randomized process, and it isn’t guaranteed to vary between runs.

Big-O: add, remove, in check — all O(1) average.

2.5 Strings

A str is an immutable sequence of characters. Any “mutation” creates a new string.

s = "hello"

# access / slicing — same as lists
s[0]                         # 'h'
s[::-1]                      # reversed string — common palindrome trick

# building / joining
"".join(["a", "b", "c"])       # "abc" — O(n), the correct way to concatenate many pieces
" ".join(["a", "b"])           # "a b"

# search
"lo" in s                    # substring check
s.find("lo")                  # index of substring, -1 if not found
s.index("lo")                 # like find, but raises ValueError if not found
s.count("l")                  # count occurrences

# transform
s.upper(); s.lower()
s.strip()                    # trim whitespace from both ends
s.strip("xy")                 # trim characters from both ends — see note below
s.replace("l", "L")            # replace all occurrences
s.split()                    # split on whitespace -> list
s.split(",")                  # split on delimiter
s.startswith("he"); s.endswith("lo")

# type checks
s.isdigit(); s.isalpha(); s.isalnum(); s.isupper(); s.islower(); s.isspace()

# formatting
f"{s} world"                  # f-string (preferred)
"{} world".format(s)           # .format()

# char <-> code point conversion (common in cipher/hash problems)
ord('a')                     # 97
chr(97)                      # 'a'

+ concatenation cost: a single s1 + s2 is O(n + m) — proportional to the combined length, since a new string is allocated and both are copied in. The real danger is doing this repeatedly inside a loop (result += ch each iteration): each += allocates a new string and re-copies everything accumulated so far, so total cost across the loop becomes O(n²). Always prefer collecting pieces in a list and calling "".join(list) once at the end.

strip("xy") does not remove the substring "xy". It treats the argument as a set of characters and strips any leading/trailing run made up of those characters, in any combination — not the literal sequence "xy".

"xyxyhelloxy".strip("xy")   # "hello" — strips leading/trailing x's and y's in any order
"xyxhelloxy".strip("xy")     # "hello" — same, order/count of x/y doesn't matter

2.6 Comprehensions

Compact syntax for building a list, dict, or set from an iterable in one line — extremely common in idiomatic Python and worth knowing cold.

# list comprehension
squares = [x**2 for x in range(5)]              # [0, 1, 4, 9, 16]
evens = [x for x in range(10) if x % 2 == 0]      # filter with condition
matrix_flat = [x for row in matrix for x in row]   # nested loop, flattens 2D -> 1D

# dict comprehension
squares_map = {x: x**2 for x in range(5)}          # {0:0, 1:1, 2:4, 3:9, 4:16}
inverted = {v: k for k, v in d.items()}             # swap keys/values

# set comprehension
unique_lengths = {len(w) for w in ["a", "bb", "cc"]}  # {1, 2}

# conditional expression inside a comprehension (ternary)
labels = ["even" if x % 2 == 0 else "odd" for x in range(5)]

Comprehensions are generally faster and more idiomatic than building the same result with a manual for loop and .append(), but nesting more than 2 levels deep hurts readability — drop to a regular loop at that point.

Section 3: Functions

3.1 Definition, Arguments & Lambda

def greet(name):
    return f"Hello, {name}"

greet("Alice")                 # "Hello, Alice"

# default arguments
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}"

greet("Alice")                 # "Hello, Alice"
greet("Alice", "Hi")            # "Hi, Alice"

# keyword arguments — pass by name, order doesn't matter
def describe(name, age):
    return f"{name} is {age}"

describe(age=30, name="Bob")      # works fine despite reversed order

# *args — collects extra positional arguments into a tuple
def total(*nums):
    return sum(nums)

total(1, 2, 3)                 # 6

# **kwargs — collects extra keyword arguments into a dict
def show(**info):
    for k, v in info.items():
        print(k, v)

show(name="Alice", age=30)

# combining all argument types (this is the required order)
def func(a, b, *args, c=10, **kwargs):
    pass

# unpacking when CALLING a function
def add(a, b, c):
    return a + b + c

nums = [1, 2, 3]
add(*nums)                     # unpacks list into positional args -> add(1, 2, 3)
kwargs = {"a": 1, "b": 2, "c": 3}
add(**kwargs)                   # unpacks dict into keyword args

# lambda — anonymous, single-expression function
square = lambda x: x ** 2
square(5)                      # 25
add_lambda = lambda a, b: a + b
# lambdas are most useful inline, e.g. as a sort key:
sorted([(1, "b"), (2, "a")], key=lambda pair: pair[1])

Mutable default argument trap: a classic bug. Default argument values are evaluated once, when the function is defined — not each time it’s called. If the default is mutable (like a list), every call that doesn’t supply that argument shares the same object, so mutations persist across calls.

def append_to(item, target=[]):    # BUG: same list reused every call
    target.append(item)
    return target

append_to(1)     # [1]
append_to(2)     # [1, 2]  <- unexpected! not a fresh list

# fix: use None as the default, create the list inside the function
def append_to(item, target=None):
    if target is None:
        target = []
    target.append(item)
    return target

3.2 First-Class Functions & Closures

Functions in Python are objects — they can be assigned to variables, passed as arguments, and returned from other functions.

def shout(text):
    return text.upper()

func = shout                  # assign function to a variable (no parens — don't call it)
func("hi")                    # "HI"

def apply(f, value):           # pass a function as an argument
    return f(value)

apply(shout, "hi")             # "HI"

# closures — an inner function that "remembers" variables from its enclosing scope
def make_multiplier(factor):
    def multiplier(x):
        return x * factor      # `factor` is captured from the enclosing scope
    return multiplier

times3 = make_multiplier(3)
times3(10)                    # 30 — remembers factor=3 even after make_multiplier() returned

3.3 Recursion

A recursive function calls itself to solve a smaller instance of the same problem. Every recursive function needs two parts:

  • Base case — the condition where the function stops calling itself and returns directly. Without this, the function recurses forever.
  • Recursive case — where the function calls itself on a smaller/simpler input, moving it closer to the base case.
def factorial(n):
    if n <= 1:                # base case
        return 1
    return n * factorial(n - 1)  # recursive case: smaller subproblem

factorial(5)                  # 120

# classic example: Fibonacci
def fib(n):
    if n <= 1:                # base case
        return n
    return fib(n - 1) + fib(n - 2)  # recursive case

Memoization — caching results of expensive recursive calls so repeated subproblems aren’t recomputed. Critical for turning exponential-time recursion into polynomial time (very common in LeetCode DP problems).

# manual memoization with a dict
def fib(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]

# built-in decorator — cleanest approach
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

Recursion limit: Python’s default recursion depth limit is 1000 (protects against stack overflow crashing the interpreter). Deep recursion (e.g. on a large linked list or deep tree) can hit RecursionError.

import sys
sys.getrecursionlimit()        # check current limit, default 1000
sys.setrecursionlimit(10000)    # raise it if truly needed (use cautiously)

Converting recursion → iteration: any recursive solution can be rewritten iteratively using an explicit stack, which avoids recursion-depth limits entirely. This is a common technique for tree/graph traversals (see Section 11).

# recursive DFS
def dfs_recursive(node):
    if not node:
        return
    print(node.val)
    dfs_recursive(node.left)
    dfs_recursive(node.right)

# iterative DFS using an explicit stack
def dfs_iterative(root):
    if not root:
        return
    stack = [root]
    while stack:
        node = stack.pop()
        print(node.val)
        if node.right: stack.append(node.right)
        if node.left:  stack.append(node.left)

Section 4: Object-Oriented Programming

4.1 Classes, __init__ & Dunder Methods

A class is a blueprint for creating objects that bundle data (attributes) and behavior (methods) together.

class Point:
    def __init__(self, x, y):    # constructor — runs when object is created
        self.x = x                # instance attribute
        self.y = y

    def distance_from_origin(self):   # regular instance method
        return (self.x ** 2 + self.y ** 2) ** 0.5

p = Point(3, 4)
p.x                          # 3
p.distance_from_origin()      # 5.0

# class attribute (shared across all instances) vs instance attribute (unique per object)
class Counter:
    count = 0                 # class attribute — shared

    def __init__(self):
        Counter.count += 1     # modifies the shared class attribute
        self.id = Counter.count  # instance attribute — unique per object

self refers to the specific instance the method is being called on — it’s always the first parameter of an instance method, and Python passes it automatically when you call obj.method().

Dunder (double-underscore) methods let your objects work with Python’s built-in syntax (print(), ==, len(), etc.) instead of needing custom method names.

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):           # controls what print(obj) / repr(obj) shows — for debugging
        return f"Point({self.x}, {self.y})"

    def __eq__(self, other):       # controls behavior of ==
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):       # controls behavior of < (enables sorted(), min(), max())
        return (self.x, self.y) < (other.x, other.y)

    def __hash__(self):           # required if you want instances usable as dict keys / in a set
        return hash((self.x, self.y))

    def __len__(self):            # controls behavior of len(obj)
        return 2

p1 = Point(1, 2)
p2 = Point(1, 2)
print(p1)                    # Point(1, 2)  — uses __repr__
p1 == p2                     # True         — uses __eq__

Most useful dunders for LeetCode-style problems: __init__, __repr__, __eq__, __lt__ (for custom sorting / heap ordering), __hash__ (to use custom objects as dict keys or set members), __len__.

4.2 Inheritance, @property, @staticmethod / @classmethod

Inheritance lets a class reuse and extend behavior from a parent class — common in LeetCode design problems (e.g. building a TreeNode hierarchy, or a custom exception).

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return f"{self.name} makes a sound"

class Dog(Animal):              # Dog inherits from Animal
    def speak(self):             # override parent method
        return f"{self.name} barks"

class Puppy(Dog):
    def __init__(self, name, age):
        super().__init__(name)    # call parent's __init__ to reuse its setup
        self.age = age

d = Dog("Rex")
d.speak()                     # "Rex barks" — overridden version used
isinstance(d, Animal)          # True — Dog is-an Animal

super() gives access to the parent class’s methods — most commonly used to call the parent’s __init__ so you don’t have to duplicate its setup logic.

@property — lets a method be accessed like an attribute (no parentheses), useful for computed values or for adding validation to attribute access.

class Circle:
    def __init__(self, radius):
        self._radius = radius     # convention: leading underscore = "internal" attribute

    @property
    def area(self):
        return 3.14159 * self._radius ** 2

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):       # runs validation when someone does circle.radius = value
        if value < 0:
            raise ValueError("radius cannot be negative")
        self._radius = value

c = Circle(5)
c.area                        # 78.53975 — called like an attribute, no parens
c.radius = 10                  # triggers the setter's validation

@staticmethod — a method that doesn’t need access to self or the class itself; it’s just grouped inside the class for organizational purposes (a plain utility function).

@classmethod — a method that receives the class itself (conventionally named cls) instead of an instance; commonly used for alternative constructors.

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    @staticmethod
    def is_valid(x, y):           # doesn't need self — pure utility function
        return isinstance(x, (int, float)) and isinstance(y, (int, float))

    @classmethod
    def from_tuple(cls, coords):    # alternative constructor
        return cls(coords[0], coords[1])

Point.is_valid(3, 4)            # True — called on the class, no instance needed
p = Point.from_tuple((3, 4))     # Point(3, 4) — alternate way to construct

Section 5: Error Handling

5.1 try / except / else / finally, Raising Errors

try:
    result = 10 / 0
except ZeroDivisionError:
    print("Can't divide by zero")

# catching multiple exception types
try:
    x = int("abc")
except (ValueError, TypeError):
    print("Bad input")

# catching the exception object itself, to inspect it
try:
    x = int("abc")
except ValueError as e:
    print(f"Error occurred: {e}")

# catching any exception (use sparingly — hides bugs if overused)
try:
    risky()
except Exception as e:
    print(f"Something went wrong: {e}")

# else — runs ONLY if no exception was raised in the try block
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Error")
else:
    print(f"Success: {result}")    # runs here, since no exception occurred

# finally — always runs, whether an exception occurred or not (cleanup code)
try:
    f = open("file.txt")
    data = f.read()
except FileNotFoundError:
    print("File not found")
finally:
    print("This always runs")       # e.g. closing resources

# raising exceptions manually
def set_age(age):
    if age < 0:
        raise ValueError("age cannot be negative")
    return age

# re-raising an exception after partially handling it
try:
    risky()
except Exception as e:
    print("Logging error...")
    raise                          # re-raises the same exception, preserving the traceback

Execution order: try runs first; if it raises, the matching except runs; if it doesn’t raise, else runs; finally runs last no matter what happened above, including if the exception was never caught.

5.2 Custom Exceptions & Common Built-in Exceptions

Custom exceptions — define your own exception types by subclassing Exception, useful for making error handling specific to your program’s logic (common in design-style LeetCode problems).

class InvalidAgeError(Exception):

class InsufficientFundsError(Exception):
    def __init__(self, balance, amount):
        self.balance = balance
        self.amount = amount
        super().__init__(f"Cannot withdraw {amount}, balance is {balance}")

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(balance, amount)
    return balance - amount

try:

7.2 deque

deque (double-ended queue) supports O(1) appends/pops from both ends, unlike a list, where operations at the front are O(n). It’s the correct structure for queues, and for sliding-window / BFS problems.

from collections import deque

d = deque([1, 2, 3])

d.append(4)                      # add to right end — O(1)
d.appendleft(0)                   # add to left end — O(1)
d.pop()                          # remove & return from right end — O(1)
d.popleft()                       # remove & return from left end — O(1)

d.extend([5, 6])                  # extend on the right
d.extendleft([0, -1])              # extend on the left (note: reverses input order)

d.rotate(1)                       # rotate right by 1: last element moves to front
d.rotate(-1)                      # rotate left by 1

deque(maxlen=3)                    # fixed-size deque — auto-drops from the opposite end when full

def bfs(start):

Section 8: Heaps & Priority Queues

8.1 heapq Basics

Python’s heapq module implements a min-heap directly on top of a regular list — there’s no separate heap type. It always keeps the smallest element accessible at heap[0], and gives O(log n) insert/remove instead of the O(n log n) it would cost to re-sort a list every time.

import heapq

heap = []
heapq.heappush(heap, 5)             # add an item — O(log n)
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)

heapq.heappop(heap)                 # remove & return the SMALLEST item — O(log n) -> 1
heap[0]                            # peek at the smallest item without removing it — O(1)

heapq.heapify(existing_list)         # convert an existing list into a heap in place — O(n)

heapq.heappushpop(heap, 4)           # push, then pop the smallest — more efficient than doing both separately
heapq.heapreplace(heap, 4)           # pop the smallest, then push — assumes heap is non-empty

# built-in helpers for direct top-k queries (avoid manually popping in a loop)
heapq.nlargest(2, [5, 1, 8, 3])       # [8, 5] — 2 largest, without fully sorting
heapq.nsmallest(2, [5, 1, 8, 3])       # [1, 3] — 2 smallest

8.2 Min-Heap vs Max-Heap Tricks

heapq only supports a min-heap natively. To simulate a max-heap, negate values on the way in and negate again on the way out.

# max-heap trick: negate every value
max_heap = []
heapq.heappush(max_heap, -5)
heapq.heappush(max_heap, -1)
heapq.heappush(max_heap, -3)

largest = -heapq.heappop(max_heap)    # negate back to get the true largest value -> 5

Pushing tuples — heaps compare elements by full tuple order, so pushing (priority, value) pairs lets you build a priority queue where the first tuple element controls ordering. This is the standard pattern for Dijkstra’s algorithm and any “process by priority” problem.

pq = []
heapq.heappush(pq, (2, "task_b"))
heapq.heappush(pq, (1, "task_a"))
heapq.heappush(pq, (3, "task_c"))

heapq.heappop(pq)                   # (1, "task_a") — lowest priority number comes first

Tie-breaking gotcha: if two tuples have the same first element, heapq compares the second element next to break the tie. If that second element isn’t directly comparable (e.g. it’s a custom object with no __lt__ defined, or two different types), this raises a TypeError. Fix by adding a unique tie-breaker in the middle of the tuple — commonly an insertion counter or index — so the comparison never needs to reach the problematic element.

# safe pattern when values aren't directly comparable
counter = 0
heapq.heappush(pq, (priority, counter, value))
counter += 1

Custom objects in a heap: define __lt__ (see Section 4.1) on your class so heapq knows how to compare instances directly, without needing to wrap them in tuples.

9.2 bisect Module

bisect performs binary search on an already-sorted list — O(log n) instead of the O(n) of a linear scan — and can also insert while keeping the list sorted.

import bisect

sorted_list = [1, 3, 4, 4, 6, 8]

bisect.bisect_left(sorted_list, 4)     # 2 — leftmost index where 4 could be inserted, keeping order
bisect.bisect_right(sorted_list, 4)     # 4 — rightmost index where 4 could be inserted
bisect.bisect(sorted_list, 4)          # same as bisect_right (default alias)

bisect.insort_left(sorted_list, 5)      # inserts 5 in sorted position, at the leftmost valid spot
bisect.insort_right(sorted_list, 5)      # inserts 5 at the rightmost valid spot
bisect.insort(sorted_list, 5)           # same as insort_right (default alias)

# common use: find if a value exists via binary search
def binary_search_exists(arr, target):
    i = bisect.bisect_left(arr, target)
    return i < len(arr) and arr[i] == target

# common use: find the smallest element >= target (lower bound)
i = bisect.bisect_left(sorted_list, target)   # arr[i] is the first element >= target (if i < len(arr))

# common use: find the largest element <= target
i = bisect.bisect_right(sorted_list, target) - 1  # arr[i] is the last element <= target (if i >= 0)

bisect_left vs bisect_right on duplicates: for a target already present in the list, bisect_left returns the index before the leftmost occurrence, while bisect_right returns the index after the rightmost occurrence. This distinction matters when you need “first position” vs “last position” of a value, or when deciding where a new equal element should land relative to existing duplicates.

Section 10: Common Algorithmic Patterns

These are reusable templates, not built-in Python features — recognizing which pattern a problem calls for is often the real difficulty in solving it.

10.1 Two Pointers

Use two indices that move through a sequence — usually toward each other (from both ends) or in the same direction at different speeds — to avoid a nested loop and get O(n) instead of O(n²).

# pattern A: pointers start at both ends, move toward each other
# classic use: checking a palindrome, or "two sum" on a sorted array
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

def two_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        curr = nums[left] + nums[right]
        if curr == target:
            return [left, right]
        elif curr < target:
            left += 1              # need a bigger sum, move left pointer up
        else:
            right -= 1              # need a smaller sum, move right pointer down
    return []

# pattern B: fast & slow pointers, moving at different speeds through the SAME sequence
# classic use: cycle detection in a linked list
def has_cycle(head):
    slow, fast = head, head
    while fast and fast.next:
        slow = slow.next            # moves 1 step
        fast = fast.next.next        # moves 2 steps
        if slow == fast:             # they meet -> cycle exists
            return True
    return False

10.2 Sliding Window

Maintain a window (a contiguous subrange, tracked by two pointers) over a sequence, expanding and shrinking it as you scan — avoids recomputing from scratch for every possible subarray/substring.

# fixed-size window: e.g. max sum of any subarray of size k
def max_sum_fixed_window(nums, k):
    window_sum = sum(nums[:k])       # initialize first window
    max_sum = window_sum
    for i in range(k, len(nums)):
        window_sum += nums[i] - nums[i - k]   # slide: add new element, drop oldest
        max_sum = max(max_sum, window_sum)
    return max_sum

# variable-size window: e.g. longest substring without repeating characters
def longest_unique_substring(s):
    seen = set()
    left = 0
    max_len = 0
    for right in range(len(s)):
        while s[right] in seen:       # shrink window from the left until valid again
            seen.remove(s[left])
            left += 1
        seen.add(s[right])
        max_len = max(max_len, right - left + 1)   # expand window on the right
    return max_len

When to reach for sliding window: the problem asks about a contiguous subarray/substring satisfying some condition (max/min length, sum, or count) — if the subrange doesn’t need to be contiguous, this pattern doesn’t apply.

10.3 Prefix Sums

Precompute cumulative sums up front so that the sum of any subarray can be answered in O(1) afterward, instead of re-summing it each time — turns many O(n) per-query problems into O(1) per-query after an O(n) setup.

def build_prefix_sums(nums):
    prefix = [0] * (len(nums) + 1)     # prefix[i] = sum of nums[0:i]
    for i in range(len(nums)):
        prefix[i + 1] = prefix[i] + nums[i]
    return prefix

# sum of nums[i:j] (inclusive i, exclusive j) in O(1):
prefix = build_prefix_sums([1, 2, 3, 4, 5])
range_sum = prefix[4] - prefix[1]       # sum of nums[1:4] = 2+3+4 = 9

# common use: "subarray sum equals k" — count subarrays using a hashmap of prefix sums seen so far
def subarray_sum_equals_k(nums, k):
    count = 0
    curr_sum = 0
    seen = {0: 1}                     # prefix sum 0 has occurred once (before any elements)
    for num in nums:
        curr_sum += num
        count += seen.get(curr_sum - k, 0)   # how many earlier prefixes would make a subarray sum to k
        seen[curr_sum] = seen.get(curr_sum, 0) + 1
    return count

11.2 Depth-First Search (DFS)

DFS explores as far as possible down one path before backtracking — implemented either with recursion (using the call stack implicitly) or with an explicit stack (see Section 3.3 for the recursion-to-iteration conversion).

# --- Tree DFS: the three standard traversal orders ---
def preorder(node, result=[]):        # visit: root -> left -> right
    if not node:
        return result
    result.append(node.val)
    preorder(node.left, result)
    preorder(node.right, result)
    return result

def inorder(node, result=[]):         # visit: left -> root -> right (gives sorted order on a BST)
    if not node:
        return result
    inorder(node.left, result)
    result.append(node.val)
    inorder(node.right, result)
    return result

def postorder(node, result=[]):       # visit: left -> right -> root
    if not node:
        return result
    postorder(node.left, result)
    postorder(node.right, result)
    result.append(node.val)
    return result

# --- Graph DFS: track visited nodes to avoid infinite loops on cycles ---
def dfs_graph(graph, start):
    visited = set()

    def explore(node):
        if node in visited:
            return
        visited.add(node)
        print(node)                    # process node
        for neighbor in graph[node]:
            explore(neighbor)

    explore(start)
    return visited

# iterative version, using an explicit stack (avoids recursion depth limits)
def dfs_graph_iterative(graph, start):
    visited = set()
    stack = [start]
    while stack:
        node = stack.pop()
        if node in visited:
            continue
        visited.add(node)
        print(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                stack.append(neighbor)
    return visited

11.3 Breadth-First Search (BFS)

BFS explores level by level, visiting all neighbors of a node before moving further out — always implemented iteratively with a queue (deque, see Section 7.2), and is the standard approach for shortest path in an unweighted graph.

from collections import deque

# tree BFS (level-order traversal)
def level_order(root):
    if not root:
        return []
    result = []
    queue = deque([root])
    while queue:
        level_size = len(queue)
        level = []
        for _ in range(level_size):      # process exactly one full level at a time
            node = queue.popleft()
            level.append(node.val)
            if node.left:  queue.append(node.left)
            if node.right: queue.append(node.right)
        result.append(level)
    return result

# graph BFS — also the template for shortest path in an unweighted graph
def bfs_graph(graph, start):
    visited = {start}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        print(node)                     # process node
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)     # mark visited AT ENQUEUE time, not at dequeue time
                queue.append(neighbor)

Why mark visited at enqueue time, not dequeue time: if you wait until a node is popped from the queue to mark it visited, the same node can be added to the queue multiple times by different neighbors before it’s ever processed — wasting time and, in graphs with cycles, potentially never terminating correctly. Marking at enqueue time guarantees each node enters the queue exactly once.

DFS vs BFS — when to use which:

Use DFS when… Use BFS when…
exploring all paths (backtracking, permutations) finding the shortest path in an unweighted graph
checking connectivity / existence of a path processing level-by-level (tree level order)
space is a concern on a wide graph (BFS queue can grow large) you need to guarantee the fewest “steps” to a target

Section 12: Backtracking & Dynamic Programming

12.1 Backtracking

Backtracking systematically explores all possible choices by building a solution incrementally, and undoing a choice (“backtracking”) as soon as it’s known to be invalid or once all its possibilities have been explored — the standard approach for permutations, combinations, and subsets.

# generic backtracking template
def backtrack(path, choices, result):
    if is_valid_solution(path):         # base case: a complete solution found
        result.append(path[:])          # append a COPY — path will keep changing after this
        return
    for choice in choices:
        if not is_valid(choice, path):    # skip invalid choices (pruning)
            continue
        path.append(choice)              # make the choice
        backtrack(path, remaining_choices, result)
        path.pop()                       # undo the choice — this IS the "backtrack" step

# concrete example: all subsets of a set
def subsets(nums):
    result = []
    def backtrack(start, path):
        result.append(path[:])           # every path is a valid subset, including empty
        for i in range(start, len(nums)):
            path.append(nums[i])
            backtrack(i + 1, path)        # move forward, don't reconsider earlier elements
            path.pop()                   # undo before trying the next option
    backtrack(0, [])
    return result

# concrete example: all permutations
def permutations(nums):
    result = []
    def backtrack(path, remaining):
        if not remaining:
            result.append(path[:])
            return
        for i in range(len(remaining)):
            path.append(remaining[i])
            backtrack(path, remaining[:i] + remaining[i+1:])   # remove chosen element
            path.pop()
    backtrack([], nums)
    return result

Why path[:] and not path: path is the same mutable list object being built and unwound throughout the whole recursion. If you append path itself to result, every entry in result ends up pointing to that same list — so once path is later modified (or emptied), all previously “saved” results change too. path[:] makes an independent copy at that moment, freezing its current contents.

Backtracking vs plain DFS: backtracking is DFS with the extra step of explicitly undoing a choice (path.pop()) after exploring it, so the same path/state object can be reused across all branches instead of creating a new one each time.

12.2 Dynamic Programming

DP solves a problem by breaking it into overlapping subproblems, solving each one once, and reusing those results — applicable when a problem has both optimal substructure (an optimal solution can be built from optimal solutions to subproblems) and overlapping subproblems (the same subproblem recurs multiple times, which is what memoization exploits).

Top-down (memoization) — write the natural recursive solution, then cache results so repeated subproblems are computed only once (builds directly on Section 3.3’s recursion + memoization).

from functools import lru_cache

# classic example: climbing stairs (1 or 2 steps at a time)
@lru_cache(maxsize=None)
def climb_stairs(n):
    if n <= 2:
        return n
    return climb_stairs(n - 1) + climb_stairs(n - 2)

# manual memoization with a dict, when lru_cache doesn't fit (e.g. mutable/unhashable args)
def coin_change(coins, amount, memo=None):
    if memo is None:
        memo = {}
    if amount == 0:
        return 0
    if amount < 0:
        return float('inf')
    if amount in memo:
        return memo[amount]
    memo[amount] = min(coin_change(coins, amount - c, memo) for c in coins) + 1
    return memo[amount]

Bottom-up (tabulation) — build the solution iteratively from the smallest subproblems up, storing results in a table (usually a list or 2D grid). Avoids recursion-depth limits entirely and is often more memory-efficient.

# climbing stairs, bottom-up
def climb_stairs(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]      # build up from smaller subproblems
    return dp[n]

# classic 2D DP example: longest common subsequence
def longest_common_subsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]   # dp[i][j] = LCS of text1[:i] and text2[:j]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]

# space optimization: many DP solutions only need the previous row/state,
# so a full 2D table can often be collapsed to two 1D arrays (or even one)
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    prev2, prev1 = 1, 2
    for _ in range(3, n + 1):
        prev2, prev1 = prev1, prev2 + prev1
    return prev1

Top-down vs bottom-up: top-down is usually easier to write (it mirrors the natural recursive definition) and only computes subproblems that are actually needed; bottom-up avoids recursion overhead and stack-depth limits, and makes space optimization (collapsing the table) more natural.

Section 13: Math & Bit Manipulation

13.1 Modular Arithmetic & Number Theory

Modular arithmetic is used whenever a problem asks for an answer “modulo 10^9 + 7” (common in counting/DP problems to keep numbers from overflowing) or when working with cyclic structures (e.g. circular arrays, hashing).

MOD = 10**9 + 7

(a + b) % MOD                    # safe to take mod of a sum directly
(a * b) % MOD                    # safe to take mod of a product directly
(a - b) % MOD                    # in Python this is already correct — result is non-negative
                                   # (unlike some other languages, where you'd need + MOD then % MOD again)

pow(a, b, MOD)                    # efficient modular exponentiation: (a ** b) % MOD, computed in O(log b)
                                   # much faster than (a ** b) % MOD for large b, which computes the full huge number first

# modular inverse (needed for modular division, since there's no direct "%" for division)
pow(a, MOD - 2, MOD)               # modular inverse of a, when MOD is prime (Fermat's little theorem)

GCD / LCM:

import math

math.gcd(12, 18)                  # 6 — greatest common divisor
math.lcm(4, 6)                    # 12 — least common multiple (Python 3.9+)

# lcm via gcd, if math.lcm isn't available
def lcm(a, b):
    return a * b // math.gcd(a, b)

math.gcd(12, 18, 24)               # 6 — gcd() accepts multiple arguments too

13.2 Bit Manipulation

Bitwise operators work on the binary representation of integers directly — useful for subset-generation problems, XOR-based tricks, and anywhere raw speed on integer flags matters.

# bitwise operators
5 & 3         # AND  -> 1   (0101 & 0011 = 0001)
5 | 3         # OR   -> 7   (0101 | 0011 = 0111)
5 ^ 3         # XOR  -> 6   (0101 ^ 0011 = 0110)
~5            # NOT  -> -6  (inverts all bits; equivalent to -(x+1))
5 << 1        # left shift  -> 10  (multiplies by 2)
5 >> 1        # right shift -> 2   (divides by 2, floor)

# common bit tricks
n & 1                             # checks if n is odd (1) or even (0) — faster than n % 2
n & (n - 1)                        # clears the lowest set bit — used to count set bits efficiently
n & (-n)                           # isolates the lowest set bit
n | (1 << i)                       # SET bit i to 1
n & ~(1 << i)                      # CLEAR bit i (set to 0)
n ^ (1 << i)                       # TOGGLE bit i
(n >> i) & 1                       # CHECK if bit i is set (returns 0 or 1)

# counting set bits ("population count")
bin(n).count('1')                  # simplest way: convert to binary string, count '1's
n.bit_count()                      # built-in method, Python 3.10+, more efficient

# useful XOR properties
# x ^ x == 0        (anything XORed with itself cancels out)
# x ^ 0 == x         (XOR with 0 is a no-op)
# XOR is commutative and associative — order doesn't matter
# classic use: find the single number in a list where every other number appears twice
def single_number(nums):
    result = 0
    for n in nums:
        result ^= n                # duplicates cancel out via x ^ x == 0, leaving only the unique one
    return result

# converting between binary string and int
bin(10)                           # '0b1010' — binary string representation
int('1010', 2)                     # 10 — parse a binary string back to int
int('ff', 16)                      # 255 — works for any base (e.g. hex)
format(10, 'b')                    # '1010' — binary string WITHOUT the '0b' prefix

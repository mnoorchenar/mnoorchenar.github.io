Section 3: Functions

3.1 Definition, Arguments & Lambda

def greet(name):
    return f"Hello, {name}"

greet("Alice")                 # "Hello, Alice"

# default arguments
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}"

greet("Alice")                 # "Hello, Alice"
greet("Alice", "Hi")            # "Hi, Alice"

# keyword arguments — pass by name, order doesn't matter
def describe(name, age):
    return f"{name} is {age}"

describe(age=30, name="Bob")      # works fine despite reversed order

# *args — collects extra positional arguments into a tuple
def total(*nums):
    return sum(nums)

total(1, 2, 3)                 # 6

# **kwargs — collects extra keyword arguments into a dict
def show(**info):
    for k, v in info.items():
        print(k, v)

show(name="Alice", age=30)

# combining all argument types (this is the required order)
def func(a, b, *args, c=10, **kwargs):
    pass

# unpacking when CALLING a function
def add(a, b, c):
    return a + b + c

nums = [1, 2, 3]
add(*nums)                     # unpacks list into positional args -> add(1, 2, 3)
kwargs = {"a": 1, "b": 2, "c": 3}
add(**kwargs)                   # unpacks dict into keyword args

# lambda — anonymous, single-expression function
square = lambda x: x ** 2
square(5)                      # 25
add_lambda = lambda a, b: a + b
# lambdas are most useful inline, e.g. as a sort key:
sorted([(1, "b"), (2, "a")], key=lambda pair: pair[1])

Mutable default argument trap: a classic bug. Default argument values are evaluated once, when the function is defined — not each time it’s called. If the default is mutable (like a list), every call that doesn’t supply that argument shares the same object, so mutations persist across calls.

def append_to(item, target=[]):    # BUG: same list reused every call
    target.append(item)
    return target

append_to(1)     # [1]
append_to(2)     # [1, 2]  <- unexpected! not a fresh list

# fix: use None as the default, create the list inside the function
def append_to(item, target=None):
    if target is None:
        target = []
    target.append(item)
    return target

3.2 First-Class Functions & Closures

Functions in Python are objects — they can be assigned to variables, passed as arguments, and returned from other functions.

def shout(text):
    return text.upper()

func = shout                  # assign function to a variable (no parens — don't call it)
func("hi")                    # "HI"

def apply(f, value):           # pass a function as an argument
    return f(value)

apply(shout, "hi")             # "HI"

# closures — an inner function that "remembers" variables from its enclosing scope
def make_multiplier(factor):
    def multiplier(x):
        return x * factor      # `factor` is captured from the enclosing scope
    return multiplier

times3 = make_multiplier(3)
times3(10)                    # 30 — remembers factor=3 even after make_multiplier() returned

3.3 Recursion

A recursive function calls itself to solve a smaller instance of the same problem. Every recursive function needs two parts:

  • Base case — the condition where the function stops calling itself and returns directly. Without this, the function recurses forever.
  • Recursive case — where the function calls itself on a smaller/simpler input, moving it closer to the base case.
def factorial(n):
    if n <= 1:                # base case
        return 1
    return n * factorial(n - 1)  # recursive case: smaller subproblem

factorial(5)                  # 120

# classic example: Fibonacci
def fib(n):
    if n <= 1:                # base case
        return n
    return fib(n - 1) + fib(n - 2)  # recursive case

Memoization — caching results of expensive recursive calls so repeated subproblems aren’t recomputed. Critical for turning exponential-time recursion into polynomial time (very common in LeetCode DP problems).

# manual memoization with a dict
def fib(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]

# built-in decorator — cleanest approach
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

Recursion limit: Python’s default recursion depth limit is 1000 (protects against stack overflow crashing the interpreter). Deep recursion (e.g. on a large linked list or deep tree) can hit RecursionError.

import sys
sys.getrecursionlimit()        # check current limit, default 1000
sys.setrecursionlimit(10000)    # raise it if truly needed (use cautiously)

Converting recursion → iteration: any recursive solution can be rewritten iteratively using an explicit stack, which avoids recursion-depth limits entirely. This is a common technique for tree/graph traversals (see Section 11).

# recursive DFS
def dfs_recursive(node):
    if not node:
        return
    print(node.val)
    dfs_recursive(node.left)
    dfs_recursive(node.right)

# iterative DFS using an explicit stack
def dfs_iterative(root):
    if not root:
        return
    stack = [root]
    while stack:
        node = stack.pop()
        print(node.val)
        if node.right: stack.append(node.right)
        if node.left:  stack.append(node.left)

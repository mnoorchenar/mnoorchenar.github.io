Where do guardrails go to keep an agent safe?

Use several layers. Any single one can miss something, so the next one has to catch it.

Five places to guard

Pick a threat and see which layer stops it.

User asks

    Asking is not enforcing

    Do both, but put every rule that matters in code.

    In the prompt: asking

    Please never refund over $100.

    The model can forget it or be talked out of it.

    In your code: enforcing

    if amount > 100: ask_a_person()

    It runs every time, whatever the model says.

    What to put in each place

    Start with “What it does”. That is where real damage happens.

    What comes in
    • Who is asking?
    • Is it in scope?
    • Hide private data
    What it reads
    • Treat it as data, not orders
    • Flag hidden commands
    What it does
    • User’s own access only
    • Approval for big actions
    • Five checks per call
    How long it runs
    • Step limit
    • Time and cost limit
    • Locked box for code
    What it says
    • No private data
    • No made-up facts
    • Follows your policy
    Around all five:Full logAlertsStop buttonAttack it yourself first

    When a guardrail trips

    Pick the lightest response that is still safe. If the guardrail itself breaks, block risky actions.

    FixHide the card number, then send
    AskWait for a person
    RefuseSay no and offer a safe option
    StopEnd the run and alert the team

    Before you ship

    No set of guardrails is perfect. These limit the damage when one fails.

    • At least two layers for every serious risk
    • Rules that matter live in code
    • Outside text never gives orders
    • The agent has no more access than its user
    • Someone can stop it at any time
    • Every attack you find becomes a test

Section 8: Heaps & Priority Queues

8.1 heapq Basics

Python’s heapq module implements a min-heap directly on top of a regular list — there’s no separate heap type. It always keeps the smallest element accessible at heap[0], and gives O(log n) insert/remove instead of the O(n log n) it would cost to re-sort a list every time.

import heapq

heap = []
heapq.heappush(heap, 5)             # add an item — O(log n)
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)

heapq.heappop(heap)                 # remove & return the SMALLEST item — O(log n) -> 1
heap[0]                            # peek at the smallest item without removing it — O(1)

heapq.heapify(existing_list)         # convert an existing list into a heap in place — O(n)

heapq.heappushpop(heap, 4)           # push, then pop the smallest — more efficient than doing both separately
heapq.heapreplace(heap, 4)           # pop the smallest, then push — assumes heap is non-empty

# built-in helpers for direct top-k queries (avoid manually popping in a loop)
heapq.nlargest(2, [5, 1, 8, 3])       # [8, 5] — 2 largest, without fully sorting
heapq.nsmallest(2, [5, 1, 8, 3])       # [1, 3] — 2 smallest

8.2 Min-Heap vs Max-Heap Tricks

heapq only supports a min-heap natively. To simulate a max-heap, negate values on the way in and negate again on the way out.

# max-heap trick: negate every value
max_heap = []
heapq.heappush(max_heap, -5)
heapq.heappush(max_heap, -1)
heapq.heappush(max_heap, -3)

largest = -heapq.heappop(max_heap)    # negate back to get the true largest value -> 5

Pushing tuples — heaps compare elements by full tuple order, so pushing (priority, value) pairs lets you build a priority queue where the first tuple element controls ordering. This is the standard pattern for Dijkstra’s algorithm and any “process by priority” problem.

pq = []
heapq.heappush(pq, (2, "task_b"))
heapq.heappush(pq, (1, "task_a"))
heapq.heappush(pq, (3, "task_c"))

heapq.heappop(pq)                   # (1, "task_a") — lowest priority number comes first

Tie-breaking gotcha: if two tuples have the same first element, heapq compares the second element next to break the tie. If that second element isn’t directly comparable (e.g. it’s a custom object with no __lt__ defined, or two different types), this raises a TypeError. Fix by adding a unique tie-breaker in the middle of the tuple — commonly an insertion counter or index — so the comparison never needs to reach the problematic element.

# safe pattern when values aren't directly comparable
counter = 0
heapq.heappush(pq, (priority, counter, value))
counter += 1

Custom objects in a heap: define __lt__ (see Section 4.1) on your class so heapq knows how to compare instances directly, without needing to wrap them in tuples.
